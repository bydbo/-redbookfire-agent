# E9 评测协议（S9.0，协议版本 1）

> 状态：**协议已冻结，正式实验未执行**。冻结日期 2026-10-28；事实源是
> [`E9真实效果与业务验证执行计划`](E9真实效果与业务验证执行计划（开发agent）.md)。
> 本文件把计划落成可执行口径；两者冲突时以计划的任务边界为准，指标口径以本文件为准。
>
> 本协议不改变生产检索默认行为，不关闭 E8 / S8.3，也不代表 S9.1–S9.4 已完成。

## 一、要回答的问题

1. 在独立素材和自然任务上，混合检索相对简单基线是否有收益？
2. 真实模型、数据库、队列、worker 和前端共同运行时，哪些任务能完成，代价和失败原因是什么？
3. 后续真实试用中，用户是否实际采纳素材或文案？

允许负面结论。实验完整性、产品质量和收益证据分表报告；“流程跑通”不等于“效果提升”。

## 二、冻结的样本矩阵

| 输入类型 | 开发集 | 留出集 | 合计 |
|---|---:|---:|---:|
| 文本 | 8 | 12 | 20 |
| 单图 | 4 | 6 | 10 |
| 同主题多图 | 4 | 6 | 10 |
| 混合主题多图 | 4 | 6 | 10 |
| **合计** | **20** | **30** | **50** |

- 严格无答案任务：开发集 4、留出集 6，共 10。
- 场景标签至少覆盖 `natural_naming`、`synonym`、`vague`、`wrong_label`、`cross_scene`，
  每类不少于 5 个任务；一个任务可有多个标签。
- 按事件、主题、原始需求和近重复关系建立 `group_id`；同组不得跨开发 / 留出集，同需求改写
  不得跨集。
- 固定 100 条素材，两个分区共享同一素材库；本实验只主张“固定素材库上的查询泛化”，
  不主张陌生素材库泛化。
- 多图必须是真实有序图片组；超限拒绝属于工程测试，不计入效果样本。

## 三、四种检索策略

| 标识 | 固定含义 |
|---|---|
| `keyword` | 文件名 + 素材文案的纯关键词子串匹配，按命中模式数排序，不用 RRF / 要素重排 |
| `trgm_only` | 仅 pg_trgm 字面召回，接现有要素评分与排序 |
| `vector_only` | 仅 pgvector 向量召回，接现有要素评分与排序 |
| `hybrid` | pg_trgm + pgvector，接现有 RRF、要素评分与排序 |

- 四策略必须复用真实召回和排序实现，不复制 SQL，不用极端阈值“模拟关闭通道”。
- 同次线索的查询向量在 vector / hybrid 之间共享，只计一次 embedding 费用。
- 报告保留通道原始排名与最终排名，区分召回失败和重排失败。
- 首版保留并披露各策略搜索字段差异；结论限定为“当前检索策略比较”。

## 四、oracle 与真实拆解

- **oracle**：由人工确认的预标注要素和关键词构造，不读取模型输出；每任务执行一次排序评测。
- **真实拆解**：自然文字 / 有序图片进入现有拆解入口；每任务 3 次，150 次都实际调用，
  不能复制第一次结果。
- 同任务同次拆解结果供四策略共享；保存实际查询向量文本摘要。
- 真实拆解失败、超时或没有线索时，有答案任务的质量指标记 0，不能换一次结果补上。

## 五、相关性、指标与分母

相关性等级：`2=直接可用`、`1=明确适配后可用`、`0=无关或违反限制`。

| 指标 | 口径 |
|---|---|
| Top-1 | 有答案任务中第一条候选等级 ≥1 的比例 |
| Hit@5 | 有答案任务中前五条至少一条等级 ≥1 的比例 |
| nDCG@5 | 增益 `2^grade−1`，折扣 `log2(rank+1)`；理想排序由全库 qrel 计算 |
| 无答案误推荐率 | 技术成功的无答案尝试中，返回任意候选的比例 |
| 正确空结果率 | 正确返回空结果次数 ÷ 全部计划无答案尝试数 |
| 技术完成率 | 终态成功尝试 ÷ 全部计划尝试 |
| 端到端成功率 | 满足任务全部关键预期的首次尝试数 ÷ 20 |
| 约束遵守率 | 通过的预标注约束检查数 ÷ 全部应检查约束数 |
| 延迟 | P50 / P95，nearest-rank；同时报样本、超时和失败数 |
| 费用 | 已知用量估算、未知占用、预算占用分列 |

规则：

- 三次结果先在任务内平均，再对任务宏平均；重复不增加独立任务数。
- 有答案任务的拆解 / 检索失败或超时，Top-1、Hit@5、nDCG 均记 0。
- 无答案任务失败不算正确空结果；误推荐率只以技术成功尝试为分母。
- 无答案 nDCG 为 N/A，不进入有答案均值。
- 未执行任务标 `not_run`；报告计划数、完成数、待执行数，不完整结果只能标阶段结果。
- 人工评分 `pass / fail / uncertain`，`uncertain` 不计通过。
- 另报“技术成功条件下”的诊断指标，但不能替代主表。

## 六、三类判定

**实验完成（evidence）**：预注册任务、重复、四策略、终态、人工评分（需要时）和证据齐全；
允许结论负面。

**质量达标（quality）**：

- 留出真实拆解 Top-1 ≥50%、Hit@5 ≥80%；
- 无答案误推荐率 ≤20%，且无答案计划尝试全部完成；
- S9.3 首次尝试任务成功率 ≥80%、约束遵守率 ≥95%；
- 不得出现伪造素材身份、错误基础版本、跨会话引用或超预算发送；
- 0.15 元 / 热点、60 秒 / 热点沿用现有目标，完整聊天、首次索引费用另列。

**收益（benefit）**：

- 留出集相对开发集选定的简单基线，`ΔnDCG@5 ≥0.05`；
- 配对 bootstrap 95% 区间下界 >0，固定种子 `20261027`、10,000 次；
- Hit@5、Top-1 不下降，无答案误推荐不增加；
- 同时披露新增费用和延迟。

三类判定互不替代：负面结果可以 evidence 通过、quality 不通过。

## 七、预算与费用守卫

- E9 新增累计上限 **10 元人民币**；S7.29、S9.4 不自动占用。
- 真实供应商凭据只给本地转发服务；API / worker / 索引使用临时配置。
- 每次发送前在持久账本预留；重试和结构修复各自预留；缺 usage、断流或进程退出转未知占用，
  重启不释放；换目录不能重置预算。
- 无价格快照、无可信上界、未通过端点 / 跨进程测试时，阻止 live 请求。
- 开发集结束重新估算；不足时保留工具和证据，不缩样本、不换模型、不减重复。

## 九、执行命令与退出码

```text
uv run python scripts/eval_e9.py validate --experiment evals/e9-v1 [--allow-draft]
uv run python scripts/e9_labels.py export --experiment evals/e9-v1 --out labels.csv
uv run python scripts/e9_labels.py import --experiment evals/e9-v1 --csv labels.csv --reviewer <审阅人>
uv run python scripts/eval_e9.py estimate --experiment evals/e9-v1
uv run python scripts/eval_e9.py index --experiment evals/e9-v1 --live \
    --database-url <隔离库 DSN>
uv run python scripts/eval_e9.py retrieval --experiment evals/e9-v1 --split dev --live \
    --database-url <隔离库 DSN>
uv run python scripts/eval_e9.py freeze-candidate --experiment evals/e9-v1
uv run python scripts/eval_e9.py retrieval --experiment evals/e9-v1 --split holdout --live \
    --database-url <隔离库 DSN>
uv run python scripts/eval_e9.py e2e --experiment evals/e9-v1
uv run python scripts/eval_e9.py e2e --experiment evals/e9-v1 --live
uv run python scripts/e9_browser_attempt.py --base-url http://127.0.0.1:8000 \
    --case-id holdout-text-001 --text "自然任务" --mode live --budget-ref <账本请求号>
uv run python scripts/eval_e9.py score --experiment evals/e9-v1 --import <人工评分.json>
uv run python scripts/eval_e9.py report --experiment evals/e9-v1
uv run python scripts/eval_e9.py check --experiment evals/e9-v1 --gate evidence
uv run python scripts/eval_e9.py check --experiment evals/e9-v1 --gate quality
```

`index` 先用 Alembic 升级显式 `--database-url` 指向的隔离库，再同步素材 / 回填向量，
写 `results/index.json`；禁止默认连接真实库。`retrieval` 要求该索引摘要存在，按
`--clue oracle|real|both` 执行；开发集允许 `--sweep`，但当前网格 runner 未接入时直接返回 4。

`e2e` 不带 `--live` 时只校验已有 `results/e2e.json`，不启动浏览器；`--live` 先过 S8.3 /
S7.29 / 数据门，再交给外部浏览器运行器。单任务运行器只负责真实 UI 提交、刷新和证据，
人工语义评分仍需另行填写；`engineering_fake` 永不进入真实汇总。

`e9_labels.py export` 生成任务 × 素材完整矩阵（首版 5,000 格）；`import` 要求逐格齐全，
`grade=1/2` 必须写理由，并生成每任务全库审阅记录。导入后仍是 draft，必须再运行封存脚本。

退出码：`0` 通过；`2` 质量 / 收益未达标；`3` 环境、配置或数据无效；`4` 依赖、预算、执行
或人工评分未完成。默认模式禁止外部模型请求；`--live` 必须通过数据、依赖、预算和运行版本
检查；`--sweep` 与留出集组合直接拒绝。
