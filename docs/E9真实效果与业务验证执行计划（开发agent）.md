## 三、S9.0：冻结实验协议

### 3.1 数据与任务矩阵

固定如下首版规模：

| 输入类型 | 开发集 | 留出集 | 合计 |
|---|---:|---:|---:|
| 文本 | 8 | 12 | 20 |
| 单图 | 4 | 6 | 10 |
| 同主题多图 | 4 | 6 | 10 |
| 混合主题多图 | 4 | 6 | 10 |
| **合计** | **20** | **30** | **50** |

其中严格无答案任务为开发集 4 个、留出集 6 个，共 10 个。

另设可重叠场景标签，至少覆盖自然命名、同义表达、模糊需求、错误标签、跨场景借用；每类不少于 5 个任务。多图使用真实有序图片组，正常输入遵守现有上传限制；超限拒绝放入工程测试，不计为模型效果样本。

按事件、主题、原始需求和近重复关系建立 `group_id`。同组任务必须落在同一分区；同一需求的改写不得横跨开发集和留出集。素材库由两组共享，这是固定素材库上的查询泛化评测，不宣称验证了陌生素材库泛化。

### 3.2 四种检索策略

| 策略标识 | 固定含义 |
|---|---|
| `keyword` | 现有关键词子串匹配，按命中数排序，不使用 RRF 或要素重排 |
| `trgm_only` | 仅 pg_trgm 召回，接现有评分与排序 |
| `vector_only` | 仅向量召回，接现有评分与排序 |
| `hybrid` | pg_trgm 与向量召回，接现有融合、评分与排序 |

不得把后两种单通道策略称为“纯数据库相似度排序”。报告保留通道原始排名和最终排名，用于区分召回失败与重排失败。

现有策略使用的搜索字段不同：关键词包含文件名，pg_trgm 主要使用标题和描述，向量使用其既定拼接文本。首版保留并披露这些差异，结论限定为**当前检索策略比较**。

### 3.3 oracle 与真实拆解

- **oracle：**由人工确认的预标注线索构造，不读取模型结果补写关键词。
- **真实拆解：**自然文字、单图或有序多图进入现有拆解入口，不向模型提供答案标注。
- 每个任务真实拆解 **3 次**，共 150 次；每次都实际调用，不能复制第一次结果。
- 同一任务、同一次拆解结果供四种策略共享；向量与混合共享该次查询向量。
- oracle 每任务执行一次排序质量评测。
- 保存实际向量查询文本摘要；oracle 与真实线索的文本构成差异必须披露。
- 实际共享费用只记一次；另报各策略独立运行时需要承担的费用构成。

### 3.4 指标定义

相关性分为：`2=直接可用`、`1=明确适配后可用`、`0=无关或违反限制`。

| 指标 | 统一口径 |
|---|---|
| Top-1 | 有答案任务中，第一条候选等级 ≥1 的比例 |
| Hit@5 | 有答案任务中，前五条至少一条等级 ≥1 的比例 |
| nDCG@5 | 增益 `2^grade−1`，折扣 `log2(rank+1)`；理想排序由全库标注计算 |
| 无答案误推荐率 | 成功完成检索的无答案尝试中，返回任意候选的比例 |
| 正确空结果率 | 正确返回空结果次数 ÷ 全部计划无答案尝试数 |
| 端到端成功率 | 满足该任务全部关键预期的首次尝试数 ÷ 20 |
| 约束遵守率 | 通过的预标注约束检查数 ÷ 全部应检查约束数 |
| 延迟 | 分阶段及整体 P50／P95，采用 nearest-rank，同行显示样本、超时和失败数 |
| 费用 | 已知用量估算、未知用量保留额、实际预算占用分别列出 |

具体规则：

- 有答案任务发生拆解失败、检索失败或超时，Top-1、Hit@5、nDCG 均记 0。
- 无答案任务的失败不能算正确空结果；同时展示技术完成率。
- 三次结果先在任务内平均，再对任务宏平均；重复不增加独立任务数。
- 无答案任务的 nDCG 为 N/A，不塞入有答案均值。
- 未执行任务标 `not_run`。报告计划数、完成数及待执行数；不完整结果只能标为阶段结果。
- 人工评分采用 `pass / fail / uncertain`，`uncertain` 不计通过。
- 单独报告“技术成功条件下”的诊断指标，不能替代主表。

### 3.5 三类判定

**实验完成：**预注册任务、重复、终态、人工评分和证据全部齐全；结论可以为负面。

**质量达标：**

- 留出真实拆解的 Top-1 ≥50%、Hit@5 ≥80%。
- 无答案误推荐率 ≤20%，且无答案预定尝试全部完成。
- S9.3 首次尝试任务成功率 ≥80%，约束遵守率 ≥95%。
- 不得出现伪造素材身份、错误基础版本、跨会话引用或超预算发送。
- 0.15 元／热点和 60 秒／热点沿用现有目标，报告实际达标比例；完整聊天任务、首次索引费用另列，不混用分母。

**证明混合策略有收益：**

- 相对开发集预先选定的简单基线，留出集 `ΔnDCG@5 ≥0.05`。
- 配对 bootstrap 95% 区间下界大于 0。
- Hit@5、Top-1 不下降，无答案误推荐不增加。
- 同时披露新增费用和延迟。

Bootstrap 固定种子 `20261027`、10,000 次，按独立主题／来源组重采样，先聚合每任务三次结果。小样本门槛只用于本轮判断，不据此宣称总体错误率已获证明。

## 四、S9.1：数据、授权与标注

### 4.1 资产组织

新增独立版本 `evals/e9-v1/`，保留旧 v1、chat 和 context 资产原样。

版本目录承载：

- 协议、任务清单、分区、场景标签和 E2E 子集；
- 脱敏素材清单、相关性标注、oracle 线索；
- 授权摘要、人工确认记录；
- 文件 hash、计数和版本 manifest。

私人原文件、完整授权凭据、原始模型输出和浏览器证据保存在忽略目录。可提交资产必须有相应授权或完成脱敏；公开可访问不等于可以任意再分发。

冻结分三层：

1. **数据冻结：**素材字节、任务、答案、分区和协议；
2. **索引冻结：**实际素材字段、规范 UUID 映射、向量及索引摘要；
3. **候选冻结：**开发集选定的参数、模型、prompt、代码及环境版本。

### 4.2 采集顺序

1. 盘点授权素材，记录来源、用途许可和模型传输许可。
2. 固定 100 条素材副本，保留自然文件名、原有说明和错误标签。
3. 采集真实需求表达，先记录任务，再生成答案。
4. 完成主题／来源分组和开发／留出分区。
5. 制作盲标表，人工确认相关性、限制和 oracle 线索。
6. 冻结 20 个 E2E 任务及其中 6 个重复任务。
7. 生成 manifest 并执行完整性检查。

不得根据检索表现补写素材说明，不得把根据答案拼出的查询算作自然查询。

### 4.3 人工标注规则

每个任务须检查整个素材库，不能只标四种算法返回的候选。首版约有 **5,000 个任务—素材关系**需要审阅；agent 可以整理预标注，最终由用户确认。

允许稀疏保存正例，但必须同时记录该任务已经完整审阅素材库。严格无答案意味着全库不存在等级 ≥1 的素材，不是 `must_hit` 为空，也不是算法没有召回。

冻结前处理全部争议。尚未确认的判断标为待确认，不自动转为 0。

采用稳定 `material_key` 与规范 UUID 映射判分，支持 E6 根相对路径；不能依赖宿主机绝对路径或工作目录。

## 五、评测工具、接口与 10 元预算

### 5.1 实现边界

新增统一 CLI 入口 `scripts/eval_e9.py`，将数据校验、指标、预算和运行编排拆成可测试的评测模块。业务运行时代码不得 import `scripts/`。

默认不新增产品 HTTP API、业务表或 Alembic 迁移。

检索服务内部增加可复用的通道选择与预计算查询向量入口，生产默认行为保持现有混合策略。四种策略复用真实召回和排序实现，不复制 SQL，不用极端阈值模拟关闭通道。

继续使用 E8 的一致性读取；新隔离数据库通过 Alembic 升级，禁止 `create_all` 替代迁移。

### 5.2 评测数据接口

至少固定以下记录：

| 记录 | 必要内容 |
|---|---|
| `Case` | case/group/split、自然输入引用、图片顺序及 hash、任务预期、oracle、场景标签 |
| `Qrel` | case、material key、等级、理由、审阅人、确认状态 |
| `Experiment` | 数据／索引／候选摘要、代码、模型、prompt、参数、时间基准、预算标识 |
| `Attempt` | case、repeat、策略、线索模式、状态、结果引用、错误、阶段延迟、费用引用 |
| `RequestUsage` | 请求标识、模型类型、尝试序号、预留、usage 状态、估算费用、未知占用 |
| `HumanScore` | attempt、评分项、pass/fail/uncertain、证据和评审人 |
| `Decision` | 实验完整性、质量判定、收益判定及缺失项 |

使用 `experiment_id / attempt_id / request_id` 保留所有尝试。同日重跑不得覆盖原报告。

### 5.3 统一费用守卫

增加**评测专用本地模型转发服务**，复用现有 FastAPI/httpx，不增加生产预算架构。

- API、worker 和索引程序作为宿主机子进程运行；Postgres、Redis 使用隔离容器。
- 文本、视觉、embedding 全部经过同一 localhost 转发服务。
- 真实供应商凭据仅提供给转发服务；业务子进程使用临时配置和本地凭据。
- 转发服务只允许冻结的模型、上游及路径，保持响应和 SSE 语义，不伪造或缓存答案。
- 单进程持有统一持久账本，使用进程锁和原子持久化；同一预算不能通过换输出目录重新开始。
- 每次实际发送前预留费用；重试和结构修复请求各自预留。
- 超时、断流、进程退出或缺 usage 保留未知占用，重启后不自动释放。
- embedding 缺 usage 不能按零费用结算。
- 不把 `run.cost_cny` 与已经包含分析费用的聊天轮次费用直接相加。

执行前按实际供应商官方资料核对价格和文本／图片／输出计费上界，保存来源日期及价格快照。不能把仓库中的估算单价当作永远有效的账单价格。

无法给某类请求建立可信保守上界时，阻断该类 live 请求。只有端点路由及跨进程覆盖测试通过后才允许付费。

### 5.4 预算执行规则

- E9 统一上限 10 元；S7.29、S9.4 不自动占用此额度。
- 先估算索引、150 次拆解、查询向量、32 次端到端以及重试／修复费用。
- 预先指定四个开发任务，各取一次作为费用探针；这些调用属于正式开发集尝试，不额外重复计费。
- 开发集结束后重新估算剩余费用，在留出集解封前核查。
- 剩余额度不足完成相应阶段时，保留工具和已有证据，列明缺口；不得偷偷缩样本、换模型或减少重复。
- 所有付费调用仍逐次执行发送前预留；估算可行不能代替硬上限。
- 用户已确定的 10 元额度内无需逐批重复申请；新增预算或改变实验范围才需要新的决定。

### 5.5 CLI 约定

以下是**待实现的接口**，不是当前已存在命令：

```text
uv run python scripts/eval_e9.py validate --experiment <目录>
uv run python scripts/eval_e9.py estimate --experiment <目录>
uv run python scripts/eval_e9.py index --experiment <目录> --live
uv run python scripts/eval_e9.py retrieval --experiment <目录> --split dev --sweep --live
uv run python scripts/eval_e9.py freeze-candidate --experiment <目录>
uv run python scripts/eval_e9.py retrieval --experiment <目录> --split holdout --live
uv run python scripts/eval_e9.py e2e --experiment <目录> --live
uv run python scripts/eval_e9.py score --experiment <目录> --import <人工评分文件>
uv run python scripts/eval_e9.py report --experiment <目录>
uv run python scripts/eval_e9.py check --experiment <目录> --gate evidence
uv run python scripts/eval_e9.py check --experiment <目录> --gate quality
```

默认模式禁止外部模型请求；`--live` 必须通过数据、依赖、预算和运行版本检查。`--sweep` 与留出集组合直接拒绝。

检查器退出码固定为：

- `0`：指定检查通过；
- `2`：质量或收益门槛未达到；
- `3`：环境、配置或数据无效；
- `4`：依赖、预算、执行或人工评分未完成。

负面结果可以通过 `evidence` 检查，同时不通过 `quality` 检查。该检查器先服务 E9，不据此自动关闭整个 S11.0。

- trgm 单通道 3 点、向量单通道 3 点、混合 9 点；
- 关键词不调参。

其余参数固定：Top-5、召回上限、RRF、要素权重、最低分、模型、prompt 和排序时间基准。先冻结实际配置快照，不从运行环境漂移读取。

对每个策略按开发集真实拆解三次的聚合结果选参：

1. 优先选择无答案误推荐率 ≤25% 的参数；
2. 再按 nDCG、Hit@5、Top-1 依次择优；
3. 再按更少误推荐、更接近生产参数、参数字典序破同分；
4. 若没有参数满足误推荐门槛，先取误推荐最低者，再应用上述质量次序，并明确标不达标。

不使用微小延迟差异破同分。oracle 使用同一组已选参数，不另行选参。

从 keyword、trgm_only、vector_only 中按同一规则选出唯一“简单基线冠军”，在查看留出结果前冻结。主要收益判断比较 hybrid 与该冠军，其余比较作描述性分析。

### 6.2 留出集执行

1. 核验 S8.3 正式关闭和数据／索引摘要。
2. 冻结候选代码、参数、模型、prompt 和运行环境。
3. 运行全部 30 个留出任务：oracle 一次，真实拆解三次。
4. 每次线索输出共享给四种策略，保存原始通道与最终排名。
5. 保留失败、空结果和未知用量，不以诊断重跑替换。
6. 自动评分后提交匿名人工审阅材料。
7. 输出逐任务差异、分组结果、主比较和置信区间。

数据库检索耗时可在固定线索／向量下额外重复 5 次，不产生模型请求；单列首次与后续读取。完整检索耗时必须包含实际需要的 embedding，不能把预计算向量的耗时标成生产整体耗时。

### 6.3 失败归因

每个失败至少分到以下一类：

- 任务或真值存在歧义；
- 拆解漏掉、误解或编造关键线索；
- 素材说明／标签问题；
- 召回未包含相关素材；
- 相关素材被评分或截断淘汰；
- 无答案场景误推荐；
- 依赖、超时或模型调用失败。

可以提出改进建议，但不在同一留出轮次边改边测。修改后的结果标为复验；需要新的独立留出版本才能再次主张未见数据验证。

## 七、S9.3：真实端到端与多图验证

### 7.1 固定任务与重复

从留出集预先选定：

| 类型 | 唯一任务数 |
|---|---:|
| 文本 | 6 |
| 单图 | 4 |
| 同主题多图 | 5 |
| 混合主题多图 | 5 |
| **合计** | **20** |

其中至少：

- 4 个无答案任务，四类输入各一个；
- 5 个带结果追问；
- 5 个带改稿；
- 6 个指定重复任务覆盖四类输入，并包含追问、改稿、无答案情形。

20 个任务均执行一次；指定 6 个再各执行两次，共 **32 次尝试**。

主成功率使用 20 个任务的第一次尝试。额外 12 次只用于指定子集的稳定性分析，不把 32 次当成 32 个独立任务。

### 7.2 真实执行路径

必须通过实际浏览器：

1. 创建新会话，输入文字、上传有序图片并提交；
2. 模型实际选择和调用工具；
3. API 真实投递到 Redis；
4. 独立 Celery worker 完成检索、解释、初稿及 E8 快照；
5. 页面显示真实结果；
6. 按任务执行追问或改稿；
7. 刷新页面，核验持久化结果、版本及报告。

禁止预先种入成功 run、使用 eager worker、替换业务工具返回，或先用 API 完成任务再仅拍截图。

工程假模型模式允许用于驱动验证，但必须标 `engineering_fake`，与真实效果结果分开。

### 7.3 评分与证据

每次尝试记录：

- 输入、图片顺序和摘要；
- session、message、turn、job、run、版本引用；
- 代码、prompt、模型、参数及索引版本；
- 界面起止状态、错误、最终结果和报告；
- 模型尝试、预算记录、阶段延迟；
- 自动检查和人工评分。

自动检查负责对象引用、状态、版本承接、落库、页面与报告一致性。人工负责语义、限制和任务完成。

无答案任务允许正确输出缺口，不要求产生候选或文案。混合主题任务按冻结预期判断是否正确澄清、分辨或停止，不强制合成一份错误线索。

连续三改、长会话和指定旧版等专项引用 S7.29 的最终报告及限制。S7.29 的旧运行器适配、补跑和原基线环境归独立前置工作包；不能通过关闭 E8 校验使其通过。

## 十、测试、验收与最终交付

### 10.1 必测场景

**数据与指标**

- nDCG 手算样例、零分母、全无答案、重复候选；
- 失败／超时／未执行的分母处理；
- 三次重复聚合与分组 bootstrap；
- 相对路径、UUID 映射及别名；
- manifest 篡改、分区泄漏、无答案标注矛盾；
- 旧冻结资产未被修改。

**检索**

- 四策略使用同一库、同次线索与固定时间；
- 关闭向量通道零 embedding 请求；
- 混代向量排除、同分排序稳定；
- 共享查询向量不重复计费；
- 向量失败不降级为字面成功；
- 留出集禁止调参；
- 默认生产检索结果回归不变。

**费用与进程**

- 预留、结算、缺 usage、重试、断流、压缩和 SSE；
- API、worker、索引、同步视觉、embedding 全部受控；
- 预算不足零发送；
- 崩溃恢复保留未知占用；
- 多客户端竞争不突破统一上限；
- 报告不泄露凭据，不重复相加父子费用。

**端到端**

- 文本、单图、两类多图、无答案；
- 真实 Redis 与独立 worker；
- 追问、改稿基础版本、刷新恢复；
- 页面、详情、HTML／Markdown 与快照一致；
- 任务失败仍保留证据及费用；
- 假模型结果无法进入真实效果汇总。
