# 评测集（evals v1）

> 本文件是**评测口径与用例格式的事实源**。用例数据在 `evals/cases/`，示例素材包在
> `evals/fixtures/demo_pack/`，版本清单在 `evals/manifest.json`。
> 产品方案 §10.1 定义场景分布与标注原则，本文件把它落成可执行的格式与判定规则。

## 一、这批评测集解决什么问题

它专门回答七个问题——前五个看质量，后两个看代价。目标值在 v1 里一律标「待实测」，
由 S2.8 的基线对比脚本把实测数字回填产品方案 §10.2。

| 维度 | 口径 | 目标值 | 判定依据 |
| --- | --- | --- | --- |
| 事实准确率 | 拆出的要素与给出的理由都能回溯到热点原文或素材真实标签/画面 | ≥ 90%（待实测） | `clue_expectations.must` / `.allowed` 的命中比例 |
| 幻觉 | 不得出现禁止要素、不得引用素材库里不存在的素材、不得编造姓名/节目名/品牌 | 0 次 | `.forbidden`、`.must_not`、`hallucination_guards` + 全局负面清单 |
| Tool 选择 | 该调的调、不该调的不调（枚举见第三节） | 100%（待实测） | `tool_expectations` + `runs` 记录与 Langfuse 链路 |
| 任务完成率 | 运行成功且标注的 must/acceptable 命中；含 Top-5 命中率（≥80%）、首选命中率（≥50%） | ≥ 80% / ≥ 50%（待实测） | `match_expectations` |
| 输出结构 | 对齐 `openapi.yaml`（RunDetail / MatchCandidate / Coverage / Draft）与报告 8 区块；每条候选必须有 `reasons`/`usage`/`recall_sources` | 100% | 契约校验 + 报告检查 |
| 成本 | 单个热点的模型调用成本 | ≤ 0.05 元 | `runs.cost_cny` |
| 速度 | 单个热点从输入到报告（不含首次建索引） | ≤ 60 秒 | `runs.latency_ms` |
| 线索覆盖度 | 被命中要素权重 ÷ 全部要素权重 | ≥ 60%（待实测） | `Coverage.ratio` + `gap_expectations` |

> 产品方案 §10.2 里的「文案可用率」（人工 1–5 分）不在这七个维度内：它的产出物是撰稿环节，
> 测量阶段在 E3 之后，v1 不做自动判定，等 LangGraph 编排落地后用同一批用例补测。

## 二、用例格式

一条用例一个文件：`evals/cases/case-NN.json`（共 20 组）。素材一律用**相对路径**引用
（相对 `evals/fixtures/demo_pack/`），不写 `Material.make_id` 的哈希，保证路径改了能立刻发现。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | ✅ | `case-01` 形式，冻结后不得改名 |
| `version` | ✅ | 必须等于 `manifest.version` |
| `scene` | ✅ | 五类场景之一，分布见第三节 |
| `hotspot` | ✅ | 用户输入的热点原文，不改写 |
| `clue_expectations.must` | ✅ | 必须拆出的要素（`{type, value}`） |
| `clue_expectations.allowed` | ✅ | 可接受的额外要素；出现不扣分 |
| `clue_expectations.forbidden` | ✅ | 禁止出现的要素（`{type, value, reason}`）——幻觉负例 |
| `match_expectations.must_hit` | ✅ | 必须召回的素材路径 |
| `match_expectations.acceptable` | ✅ | 召回算对、不召回不扣分 |
| `match_expectations.must_not` | ✅ | 召回即判错（精确率） |
| `full_gap` | 可选 | `true` = 全缺口样例，此时 `must_hit` 必须为空 |
| `gap_expectations` | 可选 | 应被判为缺口并给出补拍建议的要素 |
| `tool_expectations` | 可选 | 覆盖全局默认的工具期望 |
| `output_expectations` | 可选 | 对输出结构的额外要求 |
| `budget` | 可选 | 覆盖全局默认预算；**只允许收紧，不允许放宽** |
| `hallucination_guards` | 可选 | 本用例额外的幻觉禁令，人工核对 |
| `notes` | ✅ | 标注理由 |

## 三、枚举

- **场景**（严格按产品方案 §10.1 的分布，共 20 组）：明星运动 5、节目与影视梗 4、
  节日与节气 3、生活方式 5、职场话题 3。
- **要素 `type`**：契约里的 9 类——`ip`、`topic`、`scene`、`visual`、`emotion`、`sound`、
  `conflict`、`format`、`audience`。`value` 优先用爆点词典的取值（如 `美食探店` 而不是 `探店`），
  词典未覆盖的词（如 `跳绳`）保留原词，并用于观察"词典兜底失败、靠模型拆解补齐"的表现。
- **`tool_expectations` 取值**：
  | 值 | 含义 |
  | --- | --- |
  | `no_vision_when_sidecar` | 素材已有旁车说明时不得再调视觉模型 |
  | `vision_when_no_hint` | 无旁车说明且关键帧可用时，应走视觉打标 |
  | `recall_both_channels` | 混合召回生效：`recall_sources` 应同时出现 `literal` 与 `vector` |
  | `repair_on_bad_json` | 模型输出非法 JSON 时应触发一次自修重试，而不是直接失败 |
  | `no_embedding_when_disabled` | `[embedding].enabled = false` 时不得调用向量接口 |
  | `no_candidate_padding` | 没有相关素材时不得硬凑候选（配合全缺口样例） |
- **全局默认工具期望**：`no_vision_when_sidecar`、`recall_both_channels`、
  `no_embedding_when_disabled`。用例只在需要时用 `tool_expectations` 覆盖或补充。

## 四、全局判定规则（不写进单条用例）

- **幻觉负面清单**：不得编造热点原文里没有的姓名、品牌、节目名；不得引用素材库中不存在的
  素材；不得声称素材里出现了热点中的具体人物（明星场景一律走"同款动作/原型/平替"表述）。
- **输出结构**：以 `docs/contracts/openapi.yaml` 与产品方案 §8.1 的 8 个区块为准；
  每条候选都必须有 `reasons`（非空）与 `usage`，`recall_sources` 必须有值。
- **预算默认值**：成本 ≤ 0.05 元/热点、耗时 ≤ 60 秒/热点（含首次建索引的批次需在 notes 里说明）。

## 五、示例素材包

- 位置：`evals/fixtures/demo_pack/`；共 **19 条合成素材**（12 张图 + 7 段短视频），
  其中 16 条带同名 `.txt` 旁车说明，**3 条刻意"命名混乱、无说明"**（`未整理/`），
  用于演示文件名兜底与视觉打标前后的差别。
- 覆盖四类构图（运动 / 美食 / 职场 / 宠物），旁车文案里刻意写入了可迁移要素词
  （反差、治愈、解压、共鸣、热血、焦虑、同款、跟练、教程、测评、低门槛、打工人、新手小白…），
  让字面召回与词典识别都有东西可抓。
- 素材全部**合成**（纯色/渐变 + 中文标题文字 + 少量测试图案），零版权风险、可入库；
  整包体积 < 1 MB。
- 生成器：`uv run python scripts/make_demo_pack.py [--out DIR] [--force]`。
  缺 ffmpeg 直接报错退出（项目不做运行时降级）。**重新生成会改变字节**，
  因此冻结以入库文件为准；重跑后必须更新 manifest 哈希。

## 六、版本冻结规则（硬约束）

1. v1 冻结后**不得原地修改**用例或素材；任何调整都新增版本（`manifest.version = v2`，
   必要时另建目录），v1 必须保持可复现。
2. 每次评测结果都要记录所用 `version`；跨版本比较必须说明差异来源。
3. 冻结由 `tests/unit/test_evals_fixtures.py` 强制：改了文件却没更新 manifest 哈希、
   引用了不存在的素材、场景分布跑偏，都会直接变红。
4. 升级流程：改数据 → 用生成器/手写更新 → 更新 `manifest.json`（version、frozen_at、
   计数与哈希）→ 跑校验测试 → 提交（提交信息写明版本与改动理由）。
5. **`evals/reports/` 是评测输出、不属于冻结资产**：它不入 `manifest.json`，冻结校验
   （`tests/unit/test_evals_fixtures.py` 的"未登记文件"检查）对该目录显式豁免；用例与素材的
   字节级冻结不受影响。报告按 `<主题>-v<版本>-<日期>.md`（+ 同名 `.json`）命名，历史结果只增不改。

## 八、检索层基线对比（S2.8）

`uv run python scripts/eval_retrieval.py` 消费本评测集：在只装 `demo_pack` 的**临时 Postgres** 上
跑「纯关键词子串基线 vs 双通道混合召回」两臂对照，产出《产品方案》§10.2 的五项指标，并落
`evals/reports/retrieval-v1-<日期>.md`（+ 同名 `.json`）。

本轮口径：**oracle 线索**（用标注的 `must ∪ allowed` 构造，统一 schema 默认权重，两臂同输入）；
**正确答案 = `must_hit ∪ acceptable`**；全缺口用例（`must_hit` 为空）不进两项命中率的分母，
但计入覆盖度 / 耗时 / 成本；耗时只算单次检索（不含建索引与回填）；成本只含查询向量
（检索层无 LLM 调用）。脚本另做一小格阈值扫描，**只给数据与推荐，不改 `[retrieval]` 默认值**。
