# AI 开发说明

> 这份文档是给人看的：怎么和 AI 一起开发这个项目，规则放在哪，密钥怎么管。
> 给 AI 看的硬规则在根目录 `AGENTS.md`，两者职责不同。

## 一、规范体系的四份文件

| 文件 | 给谁看 | 作用 |
| --- | --- | --- |
| `AGENTS.md` | AI（也建议人先扫一遍） | **唯一权威规范**。AI 每次任务开始时会主动读取，是"照做"的指令 |
| `docs/开发规范.md` | 人 | 同一套规则的详细解释版，讲清每条规则的来由 |
| `docs/项目结构.md` | 人 + AI | 目录树与每个目录的职责边界 |
| `docs/技术栈.md` | 人 + AI | 当前技术栈、依赖清单与规划中的演进 |
| `docs/AI开发说明.md` | 人 | 本文件：协作方式、提需求模板、密钥操作 |

冲突时的优先级：`AGENTS.md` > `docs/开发规范.md` > 其他文档。

**只保留一份 `AGENTS.md`（在仓库根）。** 不要给子目录另建 AGENTS.md——多处规则一定会互相矛盾，最后没人知道听谁的。

## 二、怎么给 AI 提任务

一个够用的任务描述包含四件事：

1. **目标**：要达成什么效果（不是"改哪个文件"）。
2. **范围**：允许动哪些目录／文件，明确不能动什么。
3. **验收**：怎么判断做完了（跑什么命令、看到什么结果）。
4. **现状**：相关的已知情况（例如"素材索引已经能做增量，但视觉打标还没接进工作流"）。

反例："优化一下匹配算法。"——没有目标、没有范围、没有验收标准，AI 只能猜。

正例："让匹配打分把人物 IP 要素降权到 0.4，只改配置与相关测试，不动打分公式；验收是在同一批样例上 IP 相关候选排名下降。"

## 三、AI 能读能改什么

**可以自由读**：`src/`、`tests/`、`docs/`、`config/config.toml`、`config/.env.example`、`pyproject.toml`、`README.md`、`AGENTS.md`。

**改之前先说清楚**：`src/xhs_agent/schemas.py`（数据契约，改它会牵动多处）、`pyproject.toml`（依赖）、`AGENTS.md`（规范本身）。

**原则上不碰**：

- `config/.env`（真实密钥，改动需由你本人操作）
- `data/materials/`（你的真实素材，只读）
- `runs/`（运行产物，可随时重建）
- `docs/产品方案.md`、`docs/简历与面试.md`（面向外部读者，措辞需你确认）

## 四、规则怎么复用（减少反复猜测）

AI 每次新会话都不记得上次聊了什么，所以规则必须写在文件里，而不是留在对话里：

- **读取约定**：任何任务开始前先读 `AGENTS.md`，按第 1、2 节确定文件位置与边界，避免"每次都要重新解释一遍项目怎么组织"。
- **执行约定**：`AGENTS.md` 第 9 节规定了固定的五步流程（读规范 → 定位 → 改动 → 验证 → 收尾），减少随机发挥。
- **随代码演进**：规范没覆盖的情况，要求 AI 在同一次提交里把新规则写回 `AGENTS.md`。规则和代码一起长，不会变成过期文档。
- **新增目录要登记**：任何新顶层目录，先写进 `docs/项目结构.md` 再动手，否则下一个人（或下一次 AI 会话）会找不到东西。

## 五、密钥与源码分开保存

密钥永远不写进代码，也不进版本库。操作步骤：

```powershell
# 1. 从模板生成真实配置文件
Copy-Item config/.env.example config/.env

# 2. 编辑 config/.env，填入真实密钥
#    DEEPSEEK_API_KEY=xxx
#    DASHSCOPE_API_KEY=xxx

# 3. 确认它确实被忽略了（应输出匹配到的忽略规则）
git check-ignore -v config/.env
```

配套机制：

- `config/config.toml` 只放可公开的默认值（模型名、路径、阈值），**没有任何凭据**。
- `config/.env.example` 可以入库，它只有变量名和空值。
- `.gitignore` 已经有 `config/.env`、`.env`、`*.env` 三条规则，且 `.env.example` 被显式排除在外。
- 环境变量优先级高于配置文件，需要临时切模型时用 `XHS_LLM_MODEL` 之类覆盖，不用改文件。

**怀疑泄漏时的处理顺序**：先轮换密钥（这一步最重要，历史里删掉也没用），再 `git ls-files` 确认文件没被跟踪，然后用 `git log -p -- config/.env` 确认历史里没有出现过。

## 六、几个容易踩的坑

1. **不要单独移动 `src/`、`config/`、`data/`、`runs/` 中的任何一个。** 工程根是靠 `src/xhs_agent/config.py` 上溯三层算出来的，拆开之后不会报错，只会静默用错路径。
2. **示例素材包放 `evals/fixtures/demo_pack/`，不要放 `data/materials/`。** 后者整个目录被忽略规则挡住，放进去了也不会进版本库。
3. **`uv run pytest` 现在报"0 用例、退出码 5"是正常的**——`tests/` 还是空目录。第一个功能落地前必须先补测试。
4. **加依赖要论证，不为省几行代码加，也不为凑简历关键词加。** 企业级组件（FastAPI、LangGraph、pgvector 等）已列入最终技术栈，按 `docs/技术栈.md` 第四节分阶段引入，并走 `AGENTS.md` 第 6 节流程。
5. **项目不做运行时降级。** 缺 API 密钥、连不上数据库或队列时启动直接失败并报错——遇到“没密钥就跑不起来”不是 bug。
6. **Docker Desktop 必须先启动**，数据库与队列都跑在容器里；C 盘只剩约 33 GB，建议把 Docker 镜像存储位置迁到 D 盘。
7. **`probe.py` 目前是 0 字节空文件。** 它预留给启动自检，属于已知未完成项，不要误以为是损坏文件。
