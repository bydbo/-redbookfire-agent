# 小红书热点搭子 · 产品方案（业务版）

> 一句话：**别人告诉你热点有多热，热点搭子告诉你这个热点里有多少是你现在就能用的。**
>
> 版本：v1 ｜ 读者：普通用户 / 非技术读者 ｜ 本文只谈业务，不含任何技术实现内容；
> 技术架构、评测方法与实现细节见《产品方案》（`docs/产品方案.md`）。

---

## 一、这个产品是干什么的

你刷到一个热点，想蹭，但不确定自己拍过的东西能不能接上。

热点搭子帮你做三件事：

1. **把热点拆开** —— 说清它为什么火、有哪几个"蹭点"、哪些点碰了会出事；
2. **在你的素材库里找** —— 挑出真正能用的镜头，并告诉你每条为什么相关、建议怎么用；
3. **给你一版初稿** —— 标题、封面字、开头三秒、正文、话题标签、剪辑顺序。

它**不替你发内容**，也不做"猜你想拍什么"的灵感工具。它解决的是一个非常具体的问题：**在我已经拍过的东西里，哪些能接上今天的热点。**

## 二、用户视角的一天

周三晚上十点，我刷到"某顶流明星打羽毛球"冲上热搜。评论区在玩梗，品牌号已经在剪同款了。我知道这波能蹭——因为我硬盘里躺着去年秋天在球馆拍的一大堆素材：挥拍的、捡球的、跟朋友打双打的，竖屏、有光、还能用。

问题是我不知道那些文件叫什么。

`DSC_0431.MP4`、`球场_1.mp4`、`未命名 3.mov`，还有一堆导完就忘了的文件夹。我打开资源管理器，从"视频素材"翻到"录像"再翻到"剪映草稿"，一帧一帧点开看，四十分钟过去了。等我把能用的镜头挑出来，热搜已经掉出前二十，品牌号的同款早发了三轮。

热点的窗口期只有 24 到 48 小时。而我花在"找素材"上的时间，比拍这些素材的时间还长。

这天我换了个做法：把"某顶流明星打羽毛球"这句话粘进热点搭子，三分钟后拿到一张表——

五条候选镜头，按相关度排序，每条告诉我**命中了热点里的哪个点**（是"羽毛球"这个主题，还是"球场"这个场景，还是"慢动作"这个画面），**建议怎么用**（放开头三秒，还是当过程画面）。表下面还有一栏写着：这个热点你还缺"挥拍特写"，建议补拍；以及一句提醒：涉及明星本人姓名和肖像的部分不能用，走"同款动作"的表达。

最后是它给我的一版初稿：三个标题备选、一句封面字、开头三秒的设计、正文、话题标签、剪辑顺序。

我没让它替我发。我要的本来就不是"发什么"，而是**在我拍过的东西里，哪些能接上今天的热点**。

## 三、我们要解决的三个真问题

**问题一：素材检索靠记忆，而热点不等你。**
创作者的素材库会随时间膨胀到几百上千条，命名靠手写、归档靠心情。找素材的手段只剩下"记得大概在哪"和"一个个点开看"。热点的时间成本结构是反的——内容可以糙一点，但必须快。

**问题二：通用大模型看不到"我有什么"。**
让大模型写"明星打羽毛球"的文案，它能写得挺好，但它不知道我手上没有羽毛球素材、只有一段攀岩视频。写出来的东西拍不出来，等于没有。**文案问题是伪问题，素材匹配问题才是真问题。**

**问题三：热点分析工具给的是行业数据，不是我手上的可用库存。**
数据看板能告诉我"这个话题热度涨了 320%"，但答不上"我能不能蹭、用哪条素材蹭"。热度和我硬盘里的文件之间，缺一层翻译。

## 四、机会点

把"热点解析"和"私人素材检索"用一层**可解释的爆点要素模型**接起来。

热点不是要整体复制，而是可以拆成若干"蹭点"：哪些点是热度的真实来源，哪些点我用自己的素材也能复现，哪些点碰了会出事。把这层拆解摆到台面上，匹配就从"猜关键词"变成了"按要素对齐"——**能对齐的就有理由，对不齐的就明确告诉你缺什么。**

## 五、市场上已有什么，我们差在哪

| 类型 | 代表 | 提供什么 | 缺什么 |
| --- | --- | --- | --- |
| 数据看板 | 新红、千瓜 | 行业热度趋势、竞品笔记数据 | 不知道用户手上有哪些素材 |
| 通用大模型 | ChatGPT、豆包、DeepSeek | 文案、选题灵感 | 看不到私有素材库，产出无法落地 |
| 剪辑工具内 AI | 剪映 | 成片阶段的字幕、口播、配乐 | 不进素材检索环节，等素材选完才登场 |
| 平台内置创作工具 | 小红书创作助手 | 基础 AI 写作、标题优化 | 无个人素材的语义层，也不做相关性判断 |
| **小红书热点搭子（本方案）** | — | 热点 → 我的素材 → 初稿，每条结论可解释、可复现 | 单机运行，需要用户自己建素材库 |

差异化只有一句话：**别人告诉你热点有多热，热点搭子告诉你这个热点里有多少是你现在就能用的。**

## 六、服务谁，不服务谁

**主用户：囤了大量素材、但找不到的个人创作者。**

特征：更新频率在一周 2 条到日更之间；素材自拍自剪，累积了几百上千条；垂类明确（运动、美食、职场、萌宠、家居等）；对热点的态度是"想蹭但怕踩雷、想快但找不到"。

**不服务的人群**：纯搬运号（没有自有素材）、机构级内容团队（需要多人协作与素材共享，见路线图）。

## 七、三个典型使用场景

| 场景 | 触发 | 期望产出 | 频率 |
| --- | --- | --- | --- |
| 临时蹭热点 | 刷到热搜，10 分钟内想判断能不能蹭 | 候选素材 + 命中理由 + 风险提醒 | 每天 1–3 次 |
| 备稿排期 | 一次输入 3–5 个热点，横向比较 | 哪个热点覆盖度最高、哪条最快能出 | 每周 1–2 次 |
| 复盘补拍 | 发现线索里的关键要素自己都没有 | 缺口清单 + 补拍建议 | 每周 1 次 |

后两个场景是这个工具区别于"一次性热点分析"的地方：**它同时是选题助手。** "覆盖缺口"那一栏长期积累下来，就是一份"我该补拍什么"的清单。

## 八、用户看到的完整流程

```
①  粘贴热点（1 到 N 条）
        │
        ▼
②  拆解火因 ──► 为什么能火 / 爆点要素 / 可蹭角度 / 风险提醒
        │
        ▼
③  分清"能用的"和"不能碰的"
        │
        ▼
④  素材检索 ──► 候选镜头排序，每条给出：得分、命中要素、为什么相关、怎么用
        │
        ▼
⑤  覆盖缺口 ──► 哪些线索有素材、哪些没有、建议补拍什么
        │
        ▼
⑥  文案初稿 ──► 标题备选／封面字／前 3 秒／正文／话题／剪辑顺序
        │
        ▼
   报告落盘（可直接打开、可直接分享的报告文件）
```

**用户视角的操作只有三次：粘贴热点 → 等一会儿 → 看报告。**

第③步是整套流程里最容易被忽略、但最关键的一环。用户的原话是"火的线索可能有明星 IP、羽毛球，或者两者结合"——这里其实藏着两件完全不同的事：明星 IP 是**不能直接用**的（用了就是肖像和代言风险），羽毛球和球场是**可以迁移**的（我拍过就能蹭）。把这两者混在一张关键词表里，结果就是要么不敢用，要么乱用。所以方案要求把它们显式分开（见第十节）。

### 也能直接对话说

上面六步是"表单式"的走法：打开分析台、粘热点、等结果。v1 还多了一个更省事的入口——**首页就是一个对话框**：

```
打开首页 → 传一张图 / 说一句话（"帮我蹭一下这个热点"）
      ↓  过程实时可见（正在解析图片 / 正在检索 / 正在写稿）
   结果以卡片形式回到对话里（候选素材 + 文案初稿）
      ↓  刷新页面，对话还在
```

对话里能做的事：跑一次完整分析、把图片拆成热点描述与要素、查素材库里有哪些能用的、回看某次已有的分析结果、只看要素拆解与缺口、按你的要求改写文案。**你说人话，系统自己去决定该调哪一步。**

要说明的是：**流程一步没少，变的只是"谁来触发"**。排序仍然不交给模型，所以"同一批素材、同一条热点，结果一样"这个承诺依然成立——对话的措辞不承诺逐字复现。

## 九、v1 做什么、不做什么

### v1 必须能跑通

| 能力 | 说明 |
| --- | --- |
| 热点手动输入 | 支持一次粘贴 1 到 N 条热点（话题句或链接文本） |
| 爆点线索拆解 | 火因机制、要素表、可蹭角度、风险提醒、目标人群 |
| 素材库建立 | 扫描本地素材目录；支持人工写一句说明；也支持自动识别画面内容打标签 |
| 增量更新 | 只有新增或修改过的素材才重新识别，**不重复付费** |
| 相关性检索 | 按要素对齐给出候选镜头排序 |
| 匹配解释 | 每条候选必须说明命中了哪个要素、建议怎么用 |
| 覆盖缺口 | 输出缺失要素与补拍建议 |
| 文案初稿 | 标题备选、封面字、开头 3 秒、正文、话题标签、剪辑顺序 |
| 报告产出 | 一份可直接打开、可直接分享的报告，含本次运行的花费与耗时 |
| 启动前置检查 | 启动时校验必需条件，任一缺失立即明确报错 |

### v1.1 补齐（明显有价值，但不阻塞 v1）

- **多热点横向对比**：一次输入多个热点，按覆盖度与最高分排序，帮你决定先做哪个。
- **历史运行回看**：复用上周拆过的线索，避免重复分析同一个热点。
- **素材复用记录**：哪条素材被哪个热点用过，避免反复用同一批镜头。
- **自定义要素词典**：用户补充自己垂类的词（例如"飞盘""腰旗橄榄球""三坑穿搭"）。
- **旁车文件模板**：一键生成素材说明模板，降低人工打标的启动成本。

### 明确不做

- 不代替用户发布内容。
- 不生成或建议使用他人姓名、肖像、品牌代言话术。
- 不爬取平台数据（评测用自建标注样本）。
- 不做"自动帮你选题"的黑盒推荐——所有结论必须能说出理由。

## 十、核心业务规则：热点怎么拆，什么能用、什么不能碰

### 10.1 热点拆成九类要素

热点的"火因"被拆成九个维度。**同一个维度内才互相比较**，避免"羽毛球"和"热血"被算成相似。

| 类型 | 标签 | 对热度的贡献 | 含义 | 明星打球例 |
| --- | --- | --- | --- | --- |
| `topic` | 主题 | 最高 | 内容主题 | 羽毛球 |
| `ip` | 人物 IP | 很高 | 明星、达人、企业家、素人标签 | 明星艺人 |
| `scene` | 场景 | 高 | 拍摄地点与空间 | 球场 |
| `conflict` | 反差结构 | 高 | 身份反差、预期违背 | 顶流 vs 业余水平 |
| `format` | 形式 | 中高 | 同款、跟练、教程、测评 | 同款 |
| `emotion` | 情绪 | 中 | 反差、治愈、解压、共鸣 | 热血 |
| `visual` | 画面 | 中 | 慢动作、特写、对比分屏 | 慢动作 |
| `audience` | 人群 | 中低 | 打工人、学生党、宝妈 | 学生党 |
| `sound` | 声音 | 最低 | BGM、原声、口播 | 现场音 |

"贡献"这一列表达的是"这个维度对热度的权重有多大"——主题和人物 IP 最重，声音最轻。**权重可调，不写死**：不同垂类的账号可以自己调。

### 10.2 借势不直用：最重要的那条产品规则

这是本方案对原始想法最重要的一次修正。热点的要素**不能平等对待**：

| 要素类型 | 能否直接使用 | 处理方式 |
| --- | --- | --- |
| 主题 / 场景 / 画面 / 形式 / 情绪 / 人群 / 反差结构 | **可迁移** | 正常使用，是蹭热点的主力 |
| 声音 | **谨慎** | 有版权风险，只建议原创或已授权音频 |
| 人物 IP | **不可直用** | 降权，转为"同款动作 / 原型 / 平替"表达，禁止姓名与肖像 |

落地方式是**把"人物 IP"这一类的权重压低**，这样"素材里没有明星"就不会再拉低匹配分——**因为素材本来就不该靠明星才能成立。**

于是"明星打羽毛球"这个热点，在系统里长这样：

```
可蹭点（我拍过就能用）        不可蹭点（碰了会出事）
─────────────────────        ─────────────────────
topic    羽毛球               ip      明星本人姓名
scene    球场                         肖像、代言暗示
visual   慢动作
format   同款
emotion  热血
audience 学生党
```

用户拿到的不是"你要有明星才能发"，而是"**把你去年在球馆拍的挥拍镜头，用慢动作剪一遍，配一句'以为是新手，结果是高手'的开头**"。

## 十一、给出的结果凭什么可信

### 11.1 判断交给模型，排序不交给模型

这是整个产品最重要的一个取舍。原因很直白：

- 让大模型排序，**同一个热点问两次可能给出不同答案**——用户没法信，也没法复现；
- 素材库越大，成本越高（一千条素材就是一千次调用）；
- 出了错，你说不清是哪一步错了。

所以分工是：**模型负责"判断"（拆火因、写解释、写初稿），排序由一套固定的规则算。** 同样的热点 + 同样的素材库，永远得到同样的排名。

### 11.2 每条结论都必须说得出理由

每条候选素材必须带三样东西，缺一不可：

1. **命中了哪个要素**（例如"主题：羽毛球 ↔ 素材标签 羽毛球"）；
2. **为什么相关**（一句人话解释）；
3. **建议怎么用**（放开头 3 秒 / 当过程画面 / 作收尾提问镜）。

**系统里不允许出现"无理由相关"的候选。** 分数再高，也要能说出它是靠哪个要素拿到的分。这条规则同时是可信度的来源和评测的基础——**可解释的分数才能被人判定对错。**

### 11.3 覆盖缺口：告诉你"缺什么"，而不只是"有什么"

所有线索要素逐个检查是否有素材命中：

- 覆盖度高 → "线索要素都有素材覆盖，可以直接剪"。
- 覆盖度低 → 逐条列出缺口，例如"缺少【画面】慢动作相关素材 → 建议补拍或去素材库再捞"。

### 11.4 画质与时效也参与打分

- **画质适配度**：竖屏、分辨率高、时长 4–60 秒的素材得分更高（贴合小红书的形态偏好）。
- **时效加成**：30 天内入库的素材加分，一年以上的老素材减分。

也就是"同样相关"的两条镜头，更适合小红书、更新鲜的那条会排前面。

## 十二、用户最终拿到什么

一次运行产出一份**可直接打开、可直接分享**的报告（方便发给别人看）和一份便于复制的文本版。

| 区块 | 内容 |
| --- | --- |
| 机会总览 | 一张表：每个热点的覆盖度、最高分、首选素材 |
| 为什么能火 | 2–3 条机制，说明这个热点靠什么留住人 |
| 热点线索 | 要素表：类型、取值、贡献度、确信程度、依据 |
| 可蹭角度 | 3–4 条具体切入方式，用"不侵权"的表述 |
| 素材匹配榜 | 排名、素材、得分、命中要素、建议用法，附关键帧缩略图 |
| 覆盖缺口 | 缺失要素 + 补拍建议 |
| 初步文案 | 标题备选、封面字、开头 3 秒、正文、话题标签、剪辑顺序、合规提醒 |
| 本次运行 | 花了多少钱、用了多久 |

报告会**按次存档**，好处有两个：**可回看**（这周判过哪些热点、当时怎么判的）、**可对账**（哪一次花了多少钱）。

## 十三、要花多少钱

| 项目 | 花费 | 说明 |
| --- | --- | --- |
| 蹭一个热点 | **约 0.09–0.12 元** | 实测口径，门槛设为不超过 0.15 元 |
| 一天蹭 5 个热点 | 约 0.5 元 | |
| 一个月 | **约 15 元** | 按每天 5 个热点估算，落在"日用工具"的可接受区间 |
| 一轮对话 | **不超过 0.25 元** | 对话里一次工具调用（通常含一次完整分析）+ 意图判断与回复，实测三轮约 0.17 元 |
| 首次建素材库 | 一次性，几元到几十元 | 与素材条数相关；**之后只在新增或修改素材时才产生** |

**成本不会随素材库变大而变贵。** 因为排序不交给大模型，素材从 500 条涨到 5000 条，单次蹭热点的花费几乎不变——把全部交给大模型的做法则会线性涨价。

## 十四、效果目标与当前实况

| 指标 | 口径 | 目标值 | v1 当前实测 |
| --- | --- | --- | --- |
| Top-5 命中率 | 前 5 条候选里至少有一条是人工标注的正确答案 | ≥ 80% | 55.6%（放宽筛选口径后可达 100%） |
| 首选命中率 | 排第一的候选属于正确答案 | ≥ 50% | 55.6% |
| 线索覆盖度 | 被素材命中的线索要素占比 | ≥ 60% | 50.0%（放宽口径后 95.0%） |
| 单次耗时 | 一个热点从输入到报告完成 | ≤ 60 秒 | 检索环节 2.30 秒 |
| 单次成本 | 一个热点的模型花费 | ≤ 0.15 元 | 0.0926 元 |
| 文案可用率 | 人工 1–5 分打分（能否直接改写使用） | ≥ 3.5 | 待测 |

**必须说清的三点**（数字要能被相信，就不能只报好看的那半）：

1. 以上命中率与覆盖度是**在"检索环节"单独测得的**，线索由人工标注构造，不包含模型拆解与撰稿的质量；
2. 当前是把筛选口径设得比较严格时测到的数字，放宽后命中率可达 100%——**是否放宽属于产品口径决策，需要单独定，不会偷偷改**；
3. 测试用的示例素材说明是按标注要素写的，字面匹配天然占便宜，这个偏差会随真实素材库消失。

## 十五、不能碰的三条红线

蹭热点这件事的风险不在技术，在使用。方案把三条红线写进产品，而不是塞进免责声明：

**红线一：不输出他人身份信息。**
报告中不出现明星、达人、企业家的姓名，也不建议在文案中使用。涉及人物 IP 的要素一律降权，并转换为"同款动作""原型""平替"这类表述。

**红线二：不使用他人肖像与未授权素材。**
用户素材库中的文件由用户自行保证来源与授权。系统只做相关性建议，不判断版权归属，并在每份报告的合规提醒里显式说明这一点。

**红线三：不暗示代言与合作关系。**
当线索中出现人物 IP 时，系统主动提示"不要暗示商业合作或代言关系"。

声音类要素单独标注版权风险，只建议使用原创或已授权音频。

> 本工具输出的是**相关性建议**，不构成法律意见。是否发布、如何表述，由用户自行决定并承担责任。

## 十六、路线图

| 阶段 | 目标 | 关键内容 |
| --- | --- | --- |
| **v1** | 跑通一件事：热点 → 我的素材 → 初稿 | 拆解、检索、解释、缺口、初稿、报告，全部可用；另含**对话式入口**（首页对话框 + 素材库页 + 运行历史） |
| **v1.1** | 提升日常使用效率 | 多热点横向对比、素材复用记录、自定义词典、素材说明模板 |
| **v2** | 从工具走向助手 | 自动抓热榜主动推荐、发布后排期、**效果回流**（用真实数据反推哪类线索有效）、草稿导出 |
| **远期** | 团队场景 | 多人协作、共享素材库、账号矩阵管理 |

> **已提前落地**：原属 v1.1 的「历史运行回看」随 v1 一起做了（运行历史页 + 对话里读回历史结果）。

### 这个产品的长期价值

v1 解决的是"这次热点我能不能用"。但每跑一次，系统都会多留一条"热点 → 要素 → 我的素材 → 结果"的记录。当记录积累到一定量，它就能回答一个更有价值的问题：**我这个账号，历史上靠哪一类线索真正涨过粉。**

那是从"相关性匹配"走向"效果预测"的路。v1 不做，但数据必须从第一天就留出来。
