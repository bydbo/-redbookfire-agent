## 2. 修复任务与完成标准

执行顺序：**契约调整 → R01／R02 → R03 → R04／R05／R08 → R06／R07 → 完整验收 → 正式切换**。

下文包内路径以 `src/xhs_agent/` 为基准。任务编号 R01—R08 用于报告和证据关联，不另行替换现有 S6.10a—S6.13 Story。

### R01 · P1：堵住回收站根及遍历路径的链接逃逸

定位：`tools/material_paths.py` 的路径解析，以及素材服务中的回收站列举、移入、恢复、删除和清空。

实施：

- 从配置素材根建立可信边界，验证 `_trash` 本身及后续每一层路径；不能先把 `_trash` 解析到外部目录，再将外部目录视为合法根。
- 检查符号链接、junction、悬空链接及其他可能改变真实位置的路径。
- 列举和清空也使用相同校验；整次操作先完成目标预检，再执行文件修改。
- 非法路径返回明确错误，不静默跳过。已识别的越界或链接问题不得造成任何文件或数据库变化。
- 配置素材根本身沿用既有配置语义；重点拒绝其下级路径逃逸，不擅自扩展为全盘文件管理功能。

完成标准：临时 `_trash` 指向外部目录时，所有相关入口拒绝；外部哨兵文件内容及数量不变；普通回收站流程通过。

### R02 · P1：部分扫描失败时禁止生成删除计划

定位：`tools/materials.py` 的扫描及素材服务的同步规划。

实施：

- 为递归扫描增加显式错误处理，任一目录无法读取即中止。
- 将失败目录和原因转换为可识别的同步错误，不返回看似完整的部分结果。
- 只有完整扫描成功才允许计算和提交删除集合。
- 保留已有“完全空扫描不删除”规则，不借此改变正常文件删除后的同步行为。

完成标准：

- 根目录、单个子目录及扫描过程中发生读取失败时，素材行、候选、向量及索引时间均不变。
- 即使其他目录已扫描到素材，失败目录中的文件也不会被列入删除。
- 完整扫描后的正常增量更新、删除仍通过。

### R03 · P2：防止恢复覆盖旁车，补齐文件组移动失败处理

定位：素材服务的文件组移动、移入回收站和恢复流程。

实施：

- 把媒体及 `.txt`／`.md`／`.json` 旁车作为一个操作集合，移动前检查全部源和目标。
- 恢复时，目标媒体或任何将写入的旁车已存在，整组返回 409，保留双方原文件。
- 移入回收站的自动编号必须为整个文件组选择无冲突名称。
- 记录本次成功移动的文件；后续移动失败时按逆序补偿，数据库变更不得继续提交。
- 补偿失败时明确返回需要人工核对，保留本地操作记录，不覆盖现存文件、不自动反复重试。
- 不宣称文件系统与数据库具备跨资源原子事务；进程中断后的残留状态必须可定位。

完成标准：媒体冲突、旁车单独冲突、第二／第三个文件移动失败、数据库提交失败、补偿失败均有测试；正常失败路径恢复原状，无法自动恢复时证据完整且不报告成功。

### R04 · P2：让归档及来源摘要保留 JSON 数值精度

定位：迁移服务的快照、计划、归档、候选重写及核验。

实施：

- 新规则采用 PostgreSQL 原生 JSONB 表示和确定性文本作为完整记录及摘要依据；完整原记录不得经过默认 Python `float` 解码后再写回。
- 在数据库内保存归档，或使用原生 JSON 文本直接绑定回 JSONB；候选重写同样不得通过有损反序列化重建整行。
- Python 中用于排序的数值使用 Decimal；规则判断与完整原始记录分离。
- 来源摘要、归档清单、预期记录、apply 重建和 verify 使用一致的无损口径。
- 将迁移规则升级到新版本，旧未执行计划必须重新生成。不得改写旧批次来伪造保真证据。
- 旧已执行批次保留原数据和原规则核验能力，但输出明确的旧规则限制，不能声称已满足新规则的无损保证。

完成标准：包含嵌套 JSON、高精度小数、大整数、Unicode、空值、向量、时间及候选数值的原记录，经归档和隔离回填后数据库值一致；不能只比较两份已经损失精度的 Python 对象。

### R05 · P2：精确核验覆盖完整别名集合

定位：迁移计划生成及 `verify_migration()`。

实施：

- 新计划保存完整预期别名映射和相关行属性，精确核验比较实际全集、数量和目标。
- 检测多项、缺项、错误目标、自环、链、环，以及旧 ID 与活动素材 ID 冲突。
- 校验批次计划摘要、归档清单及数量，不能只信任批次内保存的计数。
- 规范目标已删除但别名保留属于合法生命周期；不得据此删除别名或按路径重新绑定。
- 历史 `audit-only` 保持有限核验语义，后续重指向须能由后续批次计划与归档解释；不输出“当前数据与旧计划完全一致”。

完成标准：额外插入一条别名也使最新批次精确核验失败；双批次再合并、目标删除、同路径新素材、归档篡改及幂等重放均符合既定语义。

### R06 · P2：说明“恢复文件”不等于“恢复历史身份”

定位：素材页单条、批量和详情删除确认，以及恢复完成提示。

统一文案语义：

- 删除前：“文件可从回收站恢复；恢复后会作为新素材入库，历史候选及旧引用不会自动恢复。”
- 恢复成功：“已作为新素材入库，历史关联未恢复。”
- 文件已恢复但索引失败时，分别展示文件状态和索引失败，不提示全部成功。

完成标准：三处删除入口和批量操作口径一致；恢复后的身份与提示一致；不改变现有后端生命周期。

### R07 · P2：展示文件缺失的真实处理结果

定位：前端素材 store 的单条及批量删除。

实施：

- 消费已有 `file_missing` 字段，无需新增平行响应字段。
- 单条缺失提示：“原文件缺失，本次仅移除索引，没有文件进入回收站。”
- 批量分别统计正常移入、文件缺失、失败三种结果。
- 失败条目保留可重试入口；刷新列表不应吞掉本次操作结果。

完成标准：单条缺失、全部缺失、部分缺失与部分失败均有前端回归和浏览器证据。

### R08 · 正式切换前置：无法验证集群身份时禁止 apply

这是用户已选择的处理方式，作为七项修复之外的切换保护一并实施。

- 允许低权限只读预检，但标明不可执行。
- apply 必须同时验证计划和目标库具有可读取的集群身份，并核对数据库名称、OID、规则、schema、实现版本及来源摘要。
- 无法读取身份时，任何写入前失败；不提供绕过参数。
- 仅将权限不足识别为相应诊断，其他数据库错误原样失败，不笼统当作权限问题。
- 正式切换前由具备权限的操作者配置所需最小权限；开发 agent 不擅自提升正式账号权限。

完成标准：两个数据完全相同的独立集群不能交叉应用计划；身份不可读取时 apply 零修改；具备权限的正确目标可执行。

公共接口与兼容约定：

- 保持现有路由及成功响应形状；旁车冲突沿用 409，路径非法沿用 400。
- 在现有错误响应结构中补充必要的失败原因，并同步 OpenAPI、生成类型和用户说明。
- 迁移计划格式及规则版本明确升级；不修改已发布迁移历史，不通过降低检查强度兼容旧计划。
- 若必须增加持久化结构，通过新的 Alembic revision 实现并验证升级边界。

## 4. 正式库切换与失败处置

**文档派发不等于已授权合并正式数据。**按 `AGENTS.md` 第 8 节，真实数据库不可逆操作须有对应授权。接手 agent 应先完成修复、隔离验证及切换包，再针对明确的目标、计划和停写窗口申请执行授权；不能在准备工作前反复询问。

切换按以下顺序执行：

1. **形成候选版本。**完成本批精确暂存、本地提交和独立审查，固定代码及镜像标识；不自动推送、合并或部署。
2. **确认实际目标。**只读核对数据库身份、revision、已有迁移批次、素材根及所有写入进程；使用脱敏标识记录，禁止输出完整 DSN。
3. **准备切换包。**列出根映射、预检问题、数量变化、备份／恢复证据、执行命令、恢复方案和停写影响。未知路径或身份问题非零时不进入 apply。
4. **取得具体切换授权。**范围覆盖停写、备份、结构升级、数据合并、版本切换和恢复服务；正式恢复旧备份不自动包含在常规切换授权中。
5. **停止并排空写入。**覆盖上传、编辑、回收站、分析、索引、后台任务及独立 CLI；确认在途事务结束、旧进程不再写入。
6. **制作最终备份。**记录备份校验和、工具版本、代码及 schema；恢复到隔离库验证可读和关键数据完整。正式媒体只读，不用真实素材执行删除恢复冒烟。
7. **执行两阶段升级。**旧库先升级到扩展结构，再生成最终计划；计划绑定最终实现和数据库身份。既有 `0013` 库按实际状态处理，不为重跑流程强制 downgrade。
8. **审查并应用最终计划。**核对最终计划与授权范围，执行 apply、精确 verify，再收口到当前约束 revision。新增差异超出授权范围时暂停确认。
9. **统一切换运行端。**API、worker、CLI 使用同一审查版本和完整素材视图。现有 Compose 会自动 `upgrade head`，切换期间必须避免它抢先越过分阶段流程。
10. **完成切换检查后恢复写入。**验证启动检查、规范键／UUID、别名、归档、旧结果和关键帧读取；正式冒烟不新增付费模型请求。保存结果，再恢复业务。

失败处置：

- apply 事务失败：保留停写，确认整体回滚，不跳组继续。
- apply 成功、后续检查失败：保持停写和新证据，优先向前修复；不能直接启动不兼容旧代码。
- 必须恢复时：先恢复至隔离目标并验证，取得对应授权后再切换；不得将 schema downgrade 当作数据恢复。
- 恢复业务后已有新数据：先保全增量，不能直接用旧备份覆盖。
- 缺授权、权限或依赖时交付已完成成果及具体阻塞项，M12 保持待验收。
