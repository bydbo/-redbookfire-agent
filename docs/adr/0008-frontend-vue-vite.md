# ADR 0008 · 前端引入 Vue 3 + Vite 工程

- 状态：已采纳
- 日期：2026-09-30
- 关联：`docs/技术栈.md` 第二节、`docs/backlog.md` 的 E5、`docs/contracts/openapi.yaml`

## 背景

原决策是"零构建静态演示页"：由 FastAPI 直接返回已有的 HTML 报告，不做前端工程。理由是本地单人工具、改动最小。

但这个判断站不住：演示页是产品的门面，而创作者工具的使用过程本身就是交互密集的——输入多个热点、轮询任务进度、逐条比对候选素材（要看关键帧图片）、查看覆盖缺口、复制文案。把这些塞进一份静态 HTML 报告里，等于把工具做成了离线文档。

从简历角度看，代价更明显：`docs/简历与面试.md` 的"技术栈"一栏里，前端部分没有可写的内容，而"AI 应用开发"岗位普遍期望候选人能独立完成一个可演示的界面。

## 备选方案

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 零构建静态页（原决策） | 零构建、零依赖、改动最小 | 无交互、无组件化；演示效果弱；简历前端一栏空白 |
| Vue 3 + Vite + TS | 国内招聘出现率最高；单文件组件上手快；与 FastAPI 配合成熟 | 引入 Node 工具链；构建产物需要挂载 |
| React + Vite + TS | 生态最大、组件库最丰富 | 本项目由后端主导，React 的心智成本与收益不成正比 |
| Next.js | SSR/SSG、SEO 友好 | 本项目是本地工具，不需要 SEO 与 SSR，多一层 Node 运行时纯属负担 |

## 决策

采用 **Vue 3 + Vite + TypeScript** 技术栈：

| 用途 | 选型 |
| --- | --- |
| 框架与构建 | Vue 3（组合式 API）+ Vite + TypeScript |
| 路由与状态 | Vue Router + Pinia |
| 组件库 | Naive UI（暗色主题开箱即用，风格现代） |
| 样式 | Tailwind CSS 负责布局与视觉定制，Naive UI 负责复杂交互组件 |
| 图表 | ECharts（覆盖度、得分分布、成本耗时） |
| 接口类型 | `openapi-typescript` 从 `docs/contracts/openapi.yaml` 生成 TS 类型 |

**样式边界**：Tailwind 只用于布局、间距与视觉定制；禁止用 Tailwind 覆盖 Naive UI 组件内部结构。两套样式体系各管一段，避免互相打架。

## 后果

**正面**

- 把 ADR 0007"契约唯一源"的价值真正兑现：契约改了，前端类型重新生成，编译期就能发现不匹配；
- 演示效果从"一份报告"变成"一个能点的工具"，面试现场可以直接操作；
- 覆盖度、得分分布用图表呈现，比表格更容易一眼看懂；
- 简历技术栈一栏补上完整的前端工程叙事。

**负面**

- 引入 Node 工具链：`node_modules` 体积大、依赖数量多，与后端"运行时零依赖"的克制形成反差；
- 构建产物需要挂载点，FastAPI 要增加静态资源服务（见 ADR 0009）；
- 工期增加约 18 人日，详见 `docs/backlog.md`；
- 前端需要单独维护一套测试与 CI 环节。

**后续**

- 前端依赖不逐一论证（生态特性所致），但**直接依赖必须在提交信息里说明理由**，且禁止同时引入第二套组件库或第二个状态管理方案；
- `frontend/dist` 与 `node_modules` 不入库，规则写入 `.gitignore`。
