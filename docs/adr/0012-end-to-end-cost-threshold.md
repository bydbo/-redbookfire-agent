# ADR 0012 · 端到端单热点成本门槛由 0.05 上调至 0.15 元

- 状态：已采纳
- 日期：2026-10-03
- 关联：`docs/产品方案.md` §10.2 / §12.2、`docs/评测集.md` 七维度、`docs/contracts/prompt契约.md` §六

## 背景

产品方案 §10.2 与评测集的「成本」维度原定 `≤ 0.05 元/热点`。这个数字写于 S3.1 之前，是按"2 次模型调用、每次约 900 输出 token"估出来的（§12.2 的那张估算表）。

E3 端到端跑通后（`evals/reports/skeleton-2026-10-03.md`）实测：**单热点 3 次 `deepseek-flash` 调用、输入 8375 / 输出 8614 token、预估成本 0.0926 元**，区间 0.09–0.12 元。差两倍以上的原因有两个，都不是缺陷：

1. 图里有 **3 个模型节点**（线索拆解 / 候选解释 / 撰稿），原估算只算了 2 个；
2. 现役模型是**推理模型**，单次输出含 2k–4k 推理 token，远超原估算的 900。

后果：`prompt契约` §六 把成本列为七维度硬门槛之一，S3.10 的 prompt 回归报告会**常年在这一项亮红灯**，回归流程因此失去准入判定能力。

## 备选方案

| 方案 | 代价 |
| --- | --- |
| 调低 `[llm].max_tokens` | `max_tokens=16000` 正是 S3.5/S3.8 为解决"空 content"抬上去的，调低有把输出截断回去的风险 |
| 换更便宜或非推理的模型 | 要同步配置契约的单价与 `技术栈.md`，且拆解质量可能下降 |
| **按实测修订门槛** | 属契约变更（需本 ADR），但如实反映现状 |
| 不处理 | 硬门槛常年红灯，回归流程失去意义 |

## 决策

**端到端单热点成本门槛由 `≤ 0.05 元` 上调为 `≤ 0.15 元`**：与实测对齐并保留约 25% 余量（覆盖重试与更长热点），同时仍能拦住"翻倍级"回归（例如再把 `max_tokens` 翻一倍、或再加一个模型节点）。

同步修订：产品方案 §10.2 指标表与 §12.2 成本模型、评测集七维度与预算默认值、prompt 契约 §六、README 的门槛说明。

## 后果

**正面**

- 门槛重新落在实测区间之上且有区分度：0.15 能过、0.20 不过；
- S3.10 的 prompt 回归重新具备准入判定能力；
- §12.2 的成本叙述从估算改为实测，后续换模型或调 token 上限时有真实基线可比。

**负面**

- 单热点约 0.1 元意味着"一天 5 个热点"约 0.5 元、月约 15 元，比原估的 3–8 元高一倍以上——"日用工具"的成本叙事已相应调整（§12.2 已改）。
- 要真正压回 0.05，只能换模型或调 token 预算，**不能靠改数字**；两个方向都保留在后续计划里。

**后续**

- 若把 `material_select` 收窄为只解释 Top-3、或换成非推理模型，应重新标定并考虑把门槛调回去（标定方法复用 ADR 0010 的做法）。
- 成本单价换算（美元价 × 汇率）写在 `[llm].price_in_per_m` / `price_out_per_m`，调价时同步配置契约。
