# ADR 0006 · 检索排序不交给大模型

- 状态：已采纳
- 日期：2026-09-30
- 关联：`docs/contracts/检索契约.md`、`docs/产品方案.md` §7.1

## 背景

判断"哪条素材最相关"最直觉的做法是把素材列表丢给大模型让它排序。这个项目的核心卖点之一是"结果可复现、可解释、可评测"，排序方式直接决定这三条能否成立。

## 备选方案

| 方案 | 稳定性 | 可复现 | 成本 | 可解释 |
| --- | --- | --- | --- | --- |
| 全交给大模型排序 | 差（同输入两次结果可能不同） | 否 | 随素材量线性增长 | 弱（理由由模型自述，不可复算） |
| 大模型只做重排（先召回后精排） | 中 | 否 | 随候选数增长 | 中 |
| 确定性算法排序 | 好 | 是 | 与素材量无关 | 强（每个分数可手算） |

## 决策

**排序完全交给确定性算法**：双通道召回 → RRF 融合 → 要素加权打分 → 按分数降序、平局按 ID 升序。大模型只出现在两端：前端的线索拆解与后端的解释、撰稿。

需要特别说明的是：**引入向量召回并不违反本决策**。语义召回同样是确定性检索——同一批向量、同一套相似度计算，结果可以复算。改变的是召回手段，而不是把排序权交给模型。

## 后果

**正面**

- 同一素材库快照 + 同一热点，永远得到相同排序，评测才有意义；
- 每个候选分数可以手算复现，面试时能在白板上推演；
- 成本与素材量解耦，素材库越大优势越明显。

**负面**

- 无法利用大模型对"隐性相关性"的判断力（例如画面气质的相似）；
- 需要自己维护相似度函数与权重，调参依赖评测集而非直觉。

**后续**

- 若将来引入模型重排，必须保持"默认关闭 + 可对照评测"，并补一条新 ADR 说明它如何与可复现性要求共存。
