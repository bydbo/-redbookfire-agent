# ADR 0017 · 素材根相对身份与可审计合并

- 状态：已采纳（实现与验收进行中）
- 日期：2026-10-19
- 关联：E6 主题三 S6.10–S6.13；数据契约 §七；E8

## 背景

素材 path 保存进程绝对路径，使宿主机和容器将同一素材索引成多条记录。直接更新 ID
会碰撞 run_matches 的复合主键，直接删除又会级联丢失候选。E7 还保存了 JSON 中的旧 ID。

## 决策

一个数据库对应一个逻辑素材库。path 使用素材根相对正斜杠键，保留 UUID；支持项目外目录。
旧数据使用显式根映射、确定性保留规则、事务归档与合并；旧 UUID 通过持久别名解析。
不以文件是否在本执行环境可见决定保留行，不扫描任意目录锚点，不全库改写历史 JSON。
归档是 migration_capture，E8 负责真正运行时快照与删除生命周期。

迁移分为结构扩展、停写数据操作、约束收口。未知映射阻断 apply。非空已迁移库不做
伪恢复式 downgrade，回退依靠切换前备份；必须演练恢复并说明切换后新数据的边界。

## 备选方案

- 绝对路径：绑定进程视角，重复身份继续发生。
- 工程根相对路径：跨盘符无法表达，退回绝对路径会再次混用口径。
- 内容哈希替换 UUID：扩大为内容去重和身份重建，本次没有此需求。
- 先完成全部 E8：扩大本批范围；本次只保全原始证据并预留清晰交接。

## 后果

所有写入口和文件消费方必须同步切换，不能新旧版本混跑。path 字段虽仍为 string，
其语义变化必须通过 API 实值测试验证。当前候选可能因去重减少，历史原记录可审计，
但删除后的完整历史展示要等 E8 完成；不能将 M12 宣称为 M13。

## 执行期补充决定（2026-10-19，实施中）

- **计划与归档绑定**：计划保存 `archive_manifest`（实体类型 / 原主键 / 原始摘要）与
  `expected_records`（目标素材、候选逐行值）。apply 在破坏性改写前先按清单核验归档；
  缺项、多项、改内容（即使重算自带摘要）都失败。归档的向量 / numeric 采用显式文本编码，
  `decode_record` 提供严格逆变换，JSONB 回填使用 `jsonb_populate_record`。
- **多批次可验证范围**：`verify --batch` 的精确模式只适用于最新批次；存在后续批次时必须
  使用 `--audit-only`（归档、别名、路径仍核验）。后续批次把目标再合并时，旧别名行在同一
  事务中重指向并归档旧行；旧批次允许"计划 target 现解析到 current"的单跳重指向，全局
  别名图仍拒绝链与环。
- **实现版本绑定**：计划记录 `HEAD+worktree:<摘要>`（源码 diff、未跟踪脚本内容与状态）。
  apply 用当前实现重新生成计划；实现变化即拒绝旧计划。
- **数据库身份**：`pg_control_system()` 权限不足时记录 `cluster_source=unavailable`，
  计划不因此伪造集群标识，由审查者人工确认；错误输出不含 DSN。
- **文件边界**：旁车写入、旁车迁移、上传月份目录都按素材根重新解析，链接 / junction /
  越界明确失败；关键帧仍以工程根为基准，索引目录不在工程根下时保留绝对路径。
- **启动检查**：`check_material_identity` 校验规范键、大小写歧义、别名链 / 环及"别名指向
  活动 ID"，非法身份作为阻断错误；媒体暂时缺失不属于身份错误。
