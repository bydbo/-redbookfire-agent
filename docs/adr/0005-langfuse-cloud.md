# ADR 0005 · 可观测选 Langfuse Cloud 而非自建

- 状态：已采纳
- 日期：2026-09-30
- 关联：`docs/contracts/配置契约.md` 第二节 2.2、`docs/技术栈.md` 第二节

## 背景

项目需要回答三类可观测问题：每次模型的 token 与成本是多少、某个热点为什么跑得慢、某次运行在哪一步失败。候选方案是自建 Langfuse 或使用其云服务。

另一个约束是本机资源：开发机 C 盘只剩约 33 GB，Docker 镜像与数据卷都紧张。

## 备选方案

| 方案 | 代价 |
| --- | --- |
| 自建 Langfuse（Docker） | Langfuse v3 需要 ClickHouse、MinIO、Redis 与 Postgres 一整套组件，镜像与数据卷占用大，本机资源不划算 |
| Langfuse Cloud（SaaS 免费层） | 依赖外部服务与网络；密钥需额外管理；数据出本机 |
| 只用 structlog 日志 | 零依赖，但缺少调用链视图与成本汇总面板；面试展示效果弱 |

## 决策

**使用 Langfuse Cloud + SDK（OpenTelemetry 协议）**，本地不部署 Langfuse 服务。`LANGFUSE_*` 三个变量齐全时启用，不齐时关闭追踪并打印 warning。

## 后果

**正面**

- 本机不需要额外容器，资源压力可控；
- 免费层足以覆盖个人项目的调用量；
- 与 OpenTelemetry 协议对齐，将来若要换成自建或其它后端，接入层不用重写。

**负面**

- 依赖外网与第三方账号，离线环境下追踪不可用（但**不影响分析主链路**）；
- 调用数据会离开本机，涉及隐私的提示词内容需要评估后再上报。

**后续**

- 上报内容默认只包含 token 数、耗时、模型名与 run_id；**不默认上报素材路径与提示词原文**，需要时显式开启；
- 可观测缺失只记 warning、不阻断启动，这一点在配置契约中已写明。
