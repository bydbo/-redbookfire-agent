# ADR 0010 · 字面召回改用 word_similarity 并重标定两条通道的阈值

- 状态：已采纳
- 日期：2026-10-02
- 关联：`docs/contracts/检索契约.md` §三 / §八 / §九、`src/xhs_agent/services/retrieval.py`、`evals/reports/retrieval-v1-2026-10-02.md`

## 背景

E2 完成后的评测显示：20 组用例下**字面召回合计为 0**，混合召回 Top-5 命中率 55.6%，
比纯关键词基线（100%）低 44.4 个百分点。当时的归因是"阈值没标定好"。

对真实素材文案做同构模拟后发现归因不成立：

- 现行 `similarity(素材长文本, 拼接查询串)` 实测只有 **0.03–0.14**，阈值 0.2 下永远不过线；
- `word_similarity(关键词, 素材文案)` 实测 **0.5–0.75**（关键词整词出现时 ≈ 1.0），可过滤且有效。

根因是**度量语义与业务意图不匹配**：`similarity(a, b)` 是对称的集合重叠度 `|A∩B| / |A∪B|`。
查询是 2–5 字中文短词、素材文案几十字时，分母被素材侧 trigram 主导，分子上限只有短词的 trigram 数，
相似度天然趋近 `3/50 ≈ 0.06`。把阈值降到 0.02 的确能召回（64 条），但等于"几乎不过滤"，
字面通道退化成全库扫描，`similarity_threshold` 这个参数失去意义——问题被掩盖，而不是被修好。

## 备选方案

| 方案 | 代价 |
| --- | --- |
| 保留 `similarity()`，把阈值降到 0.02–0.05 | 字面通道退化为近似不过滤，阈值失去区分度 |
| 换成 `word_similarity()` | 语义正确，但阈值量级变化，属 §九 破坏性变更，需重新标定并重跑评测 |
| 换 Postgres 原生全文检索 | 中文分词不友好，已在 ADR 0003 否决 |

## 决策

通道 A 改用 `word_similarity(关键词, 素材文本)`：把查询拆成关键词后逐个匹配，同一素材取各关键词的最大值，
任一关键词过阈值即召回。`similarity_threshold` 的语义随之改为 **word_similarity 阈值**，
默认值按重跑评测标定为 **0.3**（0.2–0.4 是指标平台区，取中值以避免过拟合）。

同时完成通道 B 的阈值标定：`max_cosine_distance` 由 **0.35 调整为 0.6**——实测正确素材的余弦距离约 0.376，
旧的 0.35 恰好把它挡在门外；而 0.7 起向量召回接近"不过滤"（372/380），故取 0.6。

## 后果

**正面**

- 字面通道恢复工作：字面召回合计由 0 升到 49（阈值 0.3），混合召回 Top-5 命中率 55.6% → 100%；
- 首选命中率 55.6% → 88.9%，线索覆盖度 50% → 95%，均已越过产物方案 §10.2 的目标线；
- `similarity_threshold` 重新具备区分度（0.2→55 条、0.3→49、0.4→28、0.6→24），参数重新成为有意义的旋钮。

**负面**

- 属 §九 破坏性变更：历史排序与评测数字不可比，需重跑评测（已重跑并覆盖报告）；
- 当前写法是逐行聚合，**不再走 `ix_materials_text_trgm`**（`数据契约.md` §4.1 已注明）；素材库上量后需评估切回索引友好的「逐关键词 `<%` + `pg_trgm.word_similarity_threshold`」写法；
- 阈值按 20 组示例用例标定，样本小、存在过拟合风险；真实素材库上量后应重新标定。

**后续**

- 阈值重标定的复现方式已固化在 `scripts/eval_retrieval.py` 的扫描表里；
- 素材库量级上来后评估索引写法（挂 E3 的清理条目）。
