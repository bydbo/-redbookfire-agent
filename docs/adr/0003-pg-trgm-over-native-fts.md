# ADR 0003 · 字面召回用 pg_trgm 而非原生全文检索

- 状态：已采纳
- 日期：2026-09-30
- 关联：`docs/contracts/检索契约.md` 第三节

## 背景

混合检索需要一条字面召回通道，用来抓住"关键词精确出现"的素材（例如素材标签里写着"羽毛球"，而热点主题也是"羽毛球"）。候选手段是 Postgres 原生全文检索（`to_tsvector` / `tsquery`）或三元组相似度（`pg_trgm`）。

## 备选方案

| 方案 | 对中文的表现 |
| --- | --- |
| Postgres 原生全文检索 | 内置分词器不切分中文，`to_tsvector('simple', '羽毛球')` 会把整串当一个词元，用户搜"羽毛球拍"命中不了"羽毛球"；要可用必须额外装 zhparser 等分词扩展 |
| pg_trgm 三元组 | 按字符三元组切分，天然适配中文短文本；支持 `similarity()` 模糊匹配与 GIN 索引；无需额外扩展 |

## 决策

**字面召回用 `pg_trgm`**，在 `(coalesce(title,'') || ' ' || coalesce(description,''))` 表达式上建 GIN 索引，用相似度阈值过滤。

## 后果

**正面**

- 中文短文本可以直接用，不需要引入分词扩展与词典维护；
- 模糊匹配对错别字、近形词有天然容忍度；
- 与向量召回形成互补：字面通道抓精确命中，向量通道抓语义相近。

**负面**

- 三元组索引体积比 B-tree 大，写放大更明显；
- 对长文本的区分度不如真正的全文检索，但本项目素材描述通常是短句，影响有限。

**后续**

- 若将来素材描述变长、需要更强的字面检索能力，再评估引入中文分词扩展，并按本 ADR 流程补一条替代记录。
