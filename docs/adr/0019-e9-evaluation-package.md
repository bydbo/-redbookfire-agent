# ADR 0019：E9 评测逻辑独立成内部包，不进入产品 API / 数据表

- 状态：已采纳（E9，S9.0）
- 日期：2026-10-28
- 关联：E9 执行计划、`docs/E9评测协议.md`、`docs/contracts/检索契约.md` §十二

## 背景

E9 需要四策略对照、三次真实拆解、150 + 32 次受控调用、统一费用账本、人工评分和三类检查。
这些逻辑若放进 `scripts/`，无法被 mypy / 单元测试复用；若放进 `services/`，又会把评测专用
的预算与报告概念混进生产业务。产品运行时不应 import 评测代码，也不应为一次实验新增业务表、
HTTP API 或 Alembic 迁移。

## 备选方案

1. 全部写在 `scripts/eval_e9.py`：起步快，但不可测、不可复用，违反“业务代码不得 import scripts”。
2. 放进 `services/retrieval` / `services/runs`：会在生产路径引入评测记录、费用账本和判定，
   扩大运行时职责。
3. 新建 `src/xhs_agent/evaluation/` 内部包，CLI 只做参数与 IO：评测逻辑可单测，生产不依赖。

## 决策

采用方案 3：

- `evaluation/` 只被 `scripts/eval_e9.py` 与测试 import，生产层不得 import；
- 数据格式用 Pydantic 模型，未知字段拒绝；记录写入实验目录或忽略目录，不建业务表；
- 检索服务只增加 `channels` / `query_vector` 两个可选参数，生产默认路径不变；
- 费用守卫是本地文件账本 + 本地转发服务，不进入产品预算架构；
- `scripts/` 保持薄入口，不承载指标和判定算法。

## 后果

- 评测代码纳入 mypy 严格范围、单元测试与覆盖率；新增依赖仍按 AGENTS 第 6 节评估。
- 实验数据与报告可在本地复现，但不能通过产品 API 读取；这是有意的隔离。
- 若将来要把评测结果做进产品展示，需要另立 API / 数据契约任务，不能顺手把
  `evaluation/` 暴露为业务服务。
