# 架构决策记录（ADR）

> 记录**已经做出的重要技术决策**以及当时的理由。ADR 的作用不是描述现状（那是 `docs/技术栈.md` 的事），而是回答"当初为什么这么选、否掉了什么"。

## 什么时候需要写 ADR

- 引入或移除运行时依赖；
- 改变数据模型的主键、枚举取值或破坏性字段；
- 改变检索算法、相似度函数或排序权重默认值；
- 更换外部服务（模型、嵌入、可观测、队列）；
- 任何"以后有人可能会问为什么这样"的取舍。

小改动、纯重构、文档措辞不需要 ADR。

## 编号与命名

- 文件名：`NNNN-短横线连接的英文描述.md`，编号四位、从 0001 递增，不复用、不跳号。
- 英文文件名是为了跨平台稳妥；正文一律中文。
- 决策被推翻时不删除原文件，把状态改为"已废弃"并指向替代的 ADR。

## 模板

```markdown
# ADR NNNN · 标题

- 状态：提议 / 已采纳 / 已废弃（被 ADR-XXXX 取代）
- 日期：YYYY-MM-DD
- 关联：相关文档与代码路径

## 背景
要解决的问题与约束。

## 备选方案
列出真实考虑过的选项，以及各自的代价。

## 决策
选了什么，一句话说清。

## 后果
正面、负面、后续要跟进的事。
```
