# 配置契约

> 本文档是**配置项与环境变量的唯一事实源**。启动逻辑、`.env.example` 与 `config/config.toml` 都向本契约对齐。
> 与"取消运行时降级"的定稿一致：缺失必填项时**直接启动失败**，不做任何兜底。

## 一、分层与优先级

从高到低：

```
环境变量  >  config/.env  >  config/config.toml  >  代码内默认值
```

- **密钥只允许出现在 `config/.env` 与环境变量**，`config/config.toml` 只能放可公开的默认值。
- `config/config.toml` 与 `config/.env.example` 入库；`config/.env` 被 `.gitignore` 忽略，永不入库。
- 算法参数（阈值、权重、Top-K）一律放 `config.toml`，不放环境变量——可版本化、可评审、可随代码一起回溯。

## 二、环境变量总表

### 2.1 必填项（缺失或非法即启动失败）

| 变量 | 类型 | 校验规则 | 缺失时的行为 |
| --- | --- | --- | --- |
| `DEEPSEEK_API_KEY` | string | 非空、去掉首尾空白后长度 > 0 | 打印 `E_CONFIG_MISSING: DEEPSEEK_API_KEY`，退出码 2 |
| `DASHSCOPE_API_KEY` | string | 启用多模态打标或向量召回时非空 | 打印 `E_CONFIG_MISSING: DASHSCOPE_API_KEY`，退出码 2 |
| `DATABASE_URL` | DSN | 必须以 `postgresql+asyncpg://` 开头 | 打印 `E_CONFIG_MISSING` 或 `E_CONFIG_INVALID`，退出码 2 |
| `REDIS_URL` | DSN | 必须以 `redis://` 或 `rediss://` 开头 | 同上 |

`DASHSCOPE_API_KEY` 是**辅助服务密钥**，同时承担两个用途：素材抽帧打标（多模态）与文本向量化（embedding）。两个能力的服务端点由 `[vision].base_url` 与 `[embedding].base_url` 分别配置，因此可以指向**任意 OpenAI 兼容的服务商**（默认阿里云百炼）；变量名本身也可由 `[vision].api_key_env` / `[embedding].api_key_env` 改写。换供应商属于配置变更，不需要改代码。

### 2.1.1 必填项分级生效

必填项**不是从第一天起就全部要求**，按阶段与能力分级：

| 变量 | 从哪个阶段起必填 | 说明 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | P1 | 文本模型：线索拆解与撰稿 |
| `DATABASE_URL` | P2 | 数据库建立之后 |
| `DASHSCOPE_API_KEY` | 按能力 | **仅当**多模态打标或向量召回启用时必填（`[vision].enabled` / `[embedding].enabled`）；两者都未启用则不要求 |

前置检查只校验**当前阶段**的必填项（P1 阶段只要求 `DEEPSEEK_API_KEY`）：未到阶段性要求的变量即使缺失也不阻断启动，也不会校验其格式。
| `REDIS_URL` | P3 | 队列与缓存建立之后 |

未启用的能力不要求其密钥，也不影响启动。这属于**能力裁剪**，不属于运行降级——降级的定义是"依赖本应可用却静默改用劣质路径"，与 `AGENTS.md` 第 4 节的边界一致。

**可观测三件套的处理方式**：`LANGFUSE_*` 三者齐全时启用调用追踪；不齐时**关闭追踪并打印一条 warning**。可观测属于旁路组件，关闭它不影响分析结果的正确性，因此不属于"运行链路降级"。**默认只上报元数据**（模型名 / task / run_id / token / 成本 / 延迟 / 错误状态）；`LANGFUSE_CAPTURE_CONTENT=true` 时才连提示词与产出正文一起上报（ADR 0005：不默认上报提示词原文）；上报失败同样只记日志。

## 三、config.toml 段结构

字段、默认值与取值范围由启动前置检查第 2 步校验（见第四节）。**未知段或未知字段一律视为配置错误**（退出码 2）——拼错的字段必须当场报错，不能静默忽略。密钥一律不写在本文件里（见第一节）。

### 3.1 `[llm]` 文本模型

| 字段 | 默认值 | 取值范围 / 规则 |
| --- | --- | --- |
| `provider` | `openai_compatible` | `openai_compatible`、`openai`、`deepseek`、`qwen`、`dashscope`、`compatible`（都走 OpenAI 兼容端点）；`auto` 与 `offline` 的降级语义已取消 |

### 3.12 `[chat]` 对话式入口（S7.2 起）

| 字段 | 默认值 | 取值范围 / 规则 |
| --- | --- | --- |
| `max_tool_rounds` | `3` | 1–10；一轮对话里模型最多发起几次工具调用（超限就收尾并说明，不静默继续） |
| `attachment_max_mb` | `10` | 1–100；对话里传的图片单张上限，超限返回 **400**（与热点图片解析的 10MB 口径一致），文案指明是第几张 |
| `attachment_max_count` | `9` | 1–9；一条消息里最多几张图（S7.14 多图热点）。超数量**整批拒绝**（400，不静默截断） |
| `attachment_total_max_mb` | `30` | 1–200；一条消息里所有图片的合计上限（MB），超限 400；与单张上限分别生效 |
| `history_max_messages` | `20` | 1–200；装配给 supervisor 的历史里**保留原文**（不压缩）的最近消息条数；更早的降级成摘要（S7.10） |
| `history_token_budget` | `6000` | 500–32000；历史部分的 token 预算（按 `tools/llm.py::estimate_tokens` 粗估，约 1.5 字/token）。超预算先摘要、仍超再裁剪，并在本轮消息里如实说明丢了几条（S7.10） |
| `turn_stale_seconds` | `300` | 30–86400；`status=running` 的 assistant 消息超过这个时长视为中断（API 重启等），读会话时标成 `interrupted`；**同时是阶段快照（`chat_messages.progress`）的过期判定阈值（S7.21）**，不新增配置项 |

没有环境变量覆盖项（与 `[upload]` 一致）。

`max_tool_rounds` 是**开关关闭态**下的实际生效值，也是网页能力开启时的**下界**：
`[web].enabled = true` 时单轮工具往返预算的实际生效值为 `max([chat].max_tool_rounds, 8)`
（`8` = `chat_tools.WEB_MAX_TOOL_ROUNDS`；「搜一次 → 读一页 → 接着读」不是 3 轮做得完的）。
取 `max` 而不是写死 8，是为了不把用户自己调大的值压回去。关闭时**严格等于**
`[chat].max_tool_rounds`——代码默认值仍是 `3`，不因网页能力上线而变。显式指定 `max_rounds`
的调用方（脚本 / 评测）优先于两者。实现见 `services/chat_tools.py::effective_max_rounds`，
接线在 `workflows/chat.py::run_turn`。

### 3.13 `[context]` 上下文可靠性与缓存度量（S7.23–S7.28）

| `price_cache_miss_per_m` | `null` | ≥0 或空；未命中单价；为空时前缀收益记未知 |
| `price_cache_currency` | `CNY` | 非空；价格币种，随每条成本记录留档 |
| `price_cache_version` | `''` | 价格版本标识（日期或供应商价目版本），随成本记录留档 |

约束：`mode=enforce` 且 `model_window_verified=false` 时启动不失败，但运行时降级为 `shadow` 并在
`context_assembled` 观测里写 `effective_mode=shadow`、`reason=window_unverified`（不声称窗口已核实）；
`model_window_verified=true` 时必须给出 `model_context_window`，否则配置校验失败。
`price_cache_hit_per_m` 与 `price_cache_miss_per_m` 要么都给、要么都空——只给一半视为配置错误。

`[llm]` / `[vision]` 另有三个**供应商能力开关**（v2 §3.6，均默认 `false`，须以来源日期核实后
开启，不按模型名猜协议）：`prefix_usage_supported`（响应带前缀缓存分项）、
`stream_usage_supported`（流式可请求 usage）、`thinking_toggle_supported`（可安全关闭推理）。
接口与界面显示**实际生效模式及原因**（`configured_off` / `session_not_enabled` /
`window_unverified`），不只显示配置值；off 不新增抽取、版本提交、持久缓存复用或新历史装配；
shadow 只比较候选（照常计费），不改正式 prompt / 对象 / 版本 / 工具结果；
`image_cache_enabled` 是 enforce 内的细分开关。

没有环境变量覆盖项。回退：把 `mode` 调回 `off`（或从 `enabled_sessions` 移除会话）即关闭新行为，
`state_version` / 审计 / 版本 / 缓存表**保留**，不通过删历史实现回滚。

### 3.14 `[web]` 网页工具（搜索 / 抓取）

| 字段 | 默认值 | 取值范围 / 规则 |
| --- | --- | --- |
| `enabled` | `false` | 布尔；总开关。关闭时两个网页工具都不注册给对话 agent。打开后 `search_url` 必填，由预检第 8 步真探一次 |
| `search_url` | `''` | 空或 SearXNG 实例地址；`enabled = true` 时必须非空，且实例的 `search.formats` 要包含 `json`（默认只吐 HTML） |
| `engines` | `''` | 逗号分隔的引擎名（如 `"google,bing"`）；**空 = 请求里不带 `engines=`**，用实例自己的默认引擎——不是「全部引擎」的特殊值 |
| `api_key_env` | `XHS_WEB_SEARCH_API_KEY` | 非空；密钥所在的**环境变量名**。密钥本身只从环境变量 / `.env` 解析（见下），写进 `config.toml` 会被 `extra="forbid"` 拒绝 |
| `search_timeout_s` | `15` | 1–120；单次搜索超时（秒） |
| `max_results` | `8` | 1–20；一次搜索最多取几条结果 |
| `snippet_chars` | `240` | 40–1000；每条结果摘要保留的字符数（超出截断） |
| `fetch_enabled` | `true` | 布尔；抓取工具的独立开关，关掉只留搜索 |
| `fetch_timeout_s` | `30` | 1–120；单次抓取超时（秒） |
| `fetch_max_bytes` | `2000000` | 65536–10485760；单次抓取的响应体上限（字节），超限直接失败、不静默截断 |
| `fetch_max_chars` | `20000` | 1000–50000；交给模型的正文字符上限（超出截断并在结果里说明） |
| `fetch_max_redirects` | `2` | 0–5；最多跟几次重定向 |
| `check_robots_txt` | `true` | 布尔；抓取前是否检查 `robots.txt`（礼貌约定，默认遵守） |
| `max_calls_per_turn` | `3` | 1–10；一轮对话里两个网页工具**合计**最多几次调用（与 `[chat].max_tool_rounds` 分别生效） |
| `allow_private_ips` | `false` | 布尔；**仅测试用**，为 `true` 才放行私网地址（默认禁止，防 SSRF） |
| `user_agent_autonomous` | `xhs-agent/1.0 (Autonomous)` | 非空；自主调用时的 UA，便于站点侧区分与追责 |
| `user_agent_manual` | `xhs-agent/1.0 (User-Specified)` | 非空；用户点名调用时的 UA |

密钥：`api_key` **不是字段**，按 `api_key_env`（默认 `XHS_WEB_SEARCH_API_KEY`）从环境变量 / `.env`
动态解析；为空只在预检第 8 步告警，**不视为启用前提**——公开 SearXNG 实例允许无鉴权。
除密钥变量外没有环境变量覆盖项（与 `[upload]` / `[chat]` 一致）。

## 四、启动前置检查（preflight）

按顺序执行，任一步失败即中止启动：

| 步骤 | 检查内容 | 失败行为 | 退出码 |
| --- | --- | --- | --- |
| 1 | 必填环境变量齐全且格式合法（按 §2.1.1 分级生效） | 打印缺失项与格式错误清单 | 2 |
| 2 | `config.toml` 可解析、字段类型与取值在允许范围内 | 打印出错的段与字段 | 2 |
| 3 | 数据库可连接 | 打印连接串（脱敏）与底层错误 | 3 |
| 4 | 数据库扩展 `vector` 与 `pg_trgm` 已安装，pgvector ≥ 0.5.0 | 打印当前版本与安装提示 | 3 |
| 5 | 数据库迁移版本处于最新（Alembic head） | 打印当前版本与期望版本，提示执行迁移 | 3 |
| 6 | Redis 可连接（`PING`） | 打印连接串（脱敏）与底层错误 | 3 |
| 7 | `[frontend].serve = true` 时 `frontend/dist` 存在且非空 | 打印期望路径与构建命令 | 2 |
| 8 | `[web].enabled = true` 时 `search_url` 已配，且 SearXNG 的 JSON 输出可用（`GET <search_url>/search?q=test&format=json`） | `search_url` 为空、**地址不是合法的 http(s) 写法（如漏写协议头）** → 配置错误（2）：前者打印缺失提示，后者打印 `search_url`、给「补全协议头 `http://<原值>`」的提示；HTTP 非 200（含 403）、HTTP 200 但响应不是 JSON → 配置错误（2）：打印 `search_url` 与状态码，提示检查 `search.formats`；连不上 / 超时 / DNS 解析失败 → 依赖不可用（3）：打印地址与底层错误，提示先起实例 | 2（配置）/ 3（依赖） |

**模型服务不在启动时探测**：启动即调用模型会产生实际费用，也可能因网络抖动误判。模型可用性由 `GET /api/health` 按需探测，结果不计入启动成败。

退出码约定：`2` = 配置错误，`3` = 依赖不可用。两者都必须给出**可直接照做的修复提示**，而不是只吐一个堆栈。

## 五、前端与静态资源

前端是 **Vue 3 + Vite + TypeScript 单页应用**（ADR 0008），与 API 同源部署（ADR 0009）：

| 项 | 约定 |
| --- | --- |
| 构建产物 | `frontend/dist/`，不入库，由多阶段 Docker 镜像在构建阶段生成 |
| 生产挂载 | FastAPI 把 `frontend/dist` 挂在根路径；非 `/api` 且未命中静态资源时回落到 `index.html`，交给前端路由 |
| 开发模式 | Vite dev server（默认 `http://localhost:5173`）提供前端，并把 `/api` 代理到 `http://localhost:8000` |
| 接口地址 | 前端读取 `VITE_API_BASE_URL`，默认 `/api`，开发与生产无需改代码 |
| 类型来源 | `openapi-typescript` 从 `docs/contracts/openapi.yaml` 生成 `frontend/src/api/schema.d.ts`，生成物入库 |
| 工具链版本 | Node 25.3.0；包管理器 pnpm 11.25.0；`pnpm-lock.yaml` 入库 |

`[frontend].serve = true`（生产默认）时，`dist_dir` 缺失或为空即**启动失败**（退出码 2）；开发模式设为 `false` 可只跑 API。

## 六、脱敏与日志

- 启动时打印一份**脱敏配置摘要**：密钥统一显示为 `***`（不显示长度与前后缀），DSN 隐去密码部分。
- 禁止把密钥写入日志、报告、数据库或 `runs/` 下的任何产物。
- `load_config` 对应的公开接口只返回 `has_key` 之类的布尔值，不返回密钥本身。

## 七、变更规则

1. 本契约是唯一事实源；新增或修改配置项必须同时更新：本文件、`config/.env.example`、`config/config.toml`（若属可公开默认值）、preflight 清单。
2. 新增必填项属于**破坏性变更**，必须在 `docs/adr/` 补一条 ADR 说明迁移方式（老用户如何补齐）。
3. 密钥轮换不属于契约变更，只需替换 `config/.env`，无需改代码或文档。
