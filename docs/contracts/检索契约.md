# 检索契约

> 本文档是**素材相关性检索的唯一事实源**。算法实现、评测脚本与报告口径都向本契约对齐。
> 数据表与索引定义见 `数据契约.md`，参数落位见 `配置契约.md`。

## 一、目标与不变量

| 不变量 | 含义 |
| --- | --- |
| 确定性 | 同一素材库快照 + 同一热点，必须得到完全相同的排序（含并列时的次序） |
| 可解释 | 每条候选都能说清：被哪个通道召回、命中了哪个要素、贡献多少 |
| 成本解耦 | 排序不调用大模型，成本与素材量无关，不随库大小线性增长 |
| 不做降级 | 任一依赖不可用时整个分析失败并报错，不返回"只用一半数据"的结果 |

## 二、两段式流程

```
线索（要素 + 关键词）
      │
      ├─► 通道 A 字面召回（pg_trgm）  ─┐
      │                                  ├─► 候选集 ─► RRF 融合 ─► 要素打分 ─► 最终分 ─► Top-K
      └─► 通道 B 向量召回（pgvector）  ─┘
```

**召回决定"谁进入候选"，打分决定"谁排前面"**——两者必须分开，否则无法解释某条素材为什么没出现在结果里。

## 三、召回通道

### 通道 A · 字面召回（pg_trgm）

- 查询串：线索的 `match_keywords` 与全部要素 `value` 用空格拼接。
- 匹配方式：对 `materials` 上的三元组索引做相似度过滤，`similarity(文本, 查询串) > 阈值`。
- 参数字段：`similarity_threshold`（默认 0.2）。
- 单通道召回上限：`recall_limit`（默认 50）。
- 存在原因：中文短文本不适合 Postgres 原生全文检索，pg_trgm 三元组对短串更实用。

### 通道 B · 向量召回（pgvector）

- 查询向量：由热点原文与火因机制拼接后调用 embedding 接口生成。
- 距离度量：余弦；按 `<=>` 升序取最近邻。
- 参数字段：`max_cosine_distance`（默认 0.35，等价于相似度 ≥ 0.65）。
- 单通道召回上限：`recall_limit`（同 A）。
- **素材向量文本口径**：`标签 → 标题 → 描述 → 要素值`，去重、去空后用空格连接；四部分全空时不生成向量（保持 NULL）。改动这个口径会改变历史排序，属 §九 的破坏性变更。
- **单请求批量上限**：由供应商决定，当前默认 provider（DashScope `text-embedding-v3` 兼容端点）实测为 `10`；`batch_size` 超过上限时由客户端自动拆批（不属降级）。
- 向量与 `embedding_model` 同时写入；查询时 `embedding_model` 与当前模型不符的素材视为需要重建。
- 素材 `embedding` 为 NULL 时只参与通道 A——这是**数据缺失**，不是运行降级；报告需展示"向量覆盖率"。

## 四、融合：RRF

```
rrf(m)      = Σ_c 1 / (k + rank_c(m))          # k 默认 60，c 遍历该素材被召回的通道
rrf_norm(m) = rrf(m) / max_i rrf(i)            # 在本次候选集内归一化
```

- 只被一个通道召回的素材同样参与，不因"只命中一路"被淘汰。
- 两个通道都未召回的素材**不进入候选集**，即使要素分很高——这是召回边界，需在文档中明说。
- `rrf_norm` 是**相对分**，只在本次候选集内有意义，不可跨查询比较。

## 五、要素打分与最终分

沿用现有的要素加权口径（`src/xhs_agent/tools/matching.py`）：

```
element_relevance(m) = Σ_e (w_e · c_e · t_e · sim_e) / Σ_e (w_e · c_e · t_e)
base(m)              = W_ELEMENT · element_relevance(m) + W_RRF · rrf_norm(m)
score(m)             = clamp01( base(m) · (0.9 + 0.1 · quality(m)) + recency_bonus(m) )
```

- `w_e` 要素权重、`c_e` 置信度、`t_e` 类型权重、`sim_e` 最佳相似度；分母只统计**线索侧**要素，与候选集大小无关，因此 `element_relevance` 是**绝对分、跨查询可比**。
- 默认 `W_ELEMENT = 0.7`、`W_RRF = 0.3`，两者之和必须为 1。
- `quality(m)` 沿用画质适配度（竖屏 + 高清 + 时长 4–60 秒）；`recency_bonus(m)` 沿用 30 天内 +0.02、365 天以上 −0.03。
- 类型权重支持按类型覆盖，产品规则"人物 IP 降权"通过把 `ip` 权重压到 0.4 实现（见 `docs/产品方案.md` §6.2）。
- **计算位置**：召回（pg_trgm 与 pgvector）在 SQL 内完成；**RRF 融合与要素打分在 Python 内存中完成**——候选集已被 `recall_limit` 截断（每通道 ≤ 50 条，合并后规模有限），放在 Python 便于单测与逐条复算。若将来为性能把 RRF 下推到 SQL，属实现优化，不构成契约变更。

## 六、排序、截断与稳定性

1. 候选按 `score` 降序排列。
2. **`score` 相同时按 `material_id` 升序**——这一条是确定性的保证，不允许依赖数据库返回顺序。
3. 截取 Top-K：默认 5，允许 1–20，与 API 契约的 `topk` 一致。
4. 低于 `min_score`（默认 0.15）的候选不返回。
5. 数值统一保留 4 位小数后再比较与落库，避免浮点尾差导致排序抖动。

## 七、覆盖度

- 口径沿用现有实现：被候选命中（相似度 ≥ `hit_threshold`，默认 0.5）的线索要素权重之和 ÷ 全部线索要素权重之和。
- 覆盖度**与候选集绑定**，因此报告中必须同时标注本次的 Top-K 取值，否则数字无法解读。

## 八、参数总表

| 参数 | 默认 | 允许范围 | 落位 |
| --- | --- | --- | --- |
| `similarity_threshold` | 0.2 | 0–1 | `config.toml` `[retrieval]` |
| `recall_limit` | 50 | 1–500 | `[retrieval]` |
| `max_cosine_distance` | 0.35 | 0–2 | `[retrieval]` |
| `rrf_k` | 60 | 1–1000 | `[retrieval]` |
| `w_element` | 0.7 | 0–1 | `[retrieval]` |
| `w_rrf` | 0.3 | 0–1（与 `w_element` 之和为 1） | `[retrieval]` |
| `hit_threshold` | 0.5 | 0–1 | `[retrieval]` |
| `topk` | 5 | 1–20 | `[match]` |
| `min_score` | 0.15 | 0–1 | `[match]` |
| `element_type_weights` | 见产品方案 §6.1 | 每项 0–1 | `[match]` |
| `embedding_dim` | 1024 | 必须与模型输出一致 | `[embedding]` |

## 九、破坏性变更清单

以下变更会**改变历史结果**，必须补 ADR、重建向量索引并重跑评测集：

1. 更换 embedding 模型；
2. 修改 `embedding_dim`；
3. 修改距离度量（余弦 → 内积 / 欧氏）；
4. 修改 `rrf_k` 或默认权重 `w_element` / `w_rrf`；
5. 修改文本相似度函数（例如从字符二元组改为其它算法）。
6. 修改素材向量文本口径（标签 / 标题 / 描述 / 要素值的拼接方式与顺序）。

`embedding_model` 字段记录每条素材的生成模型，用于识别"索引里混着两代向量"的状态。

## 十、失败与边界情形

| 情形 | 行为 |
| --- | --- |
| 数据库不可用 | 分析失败，错误码 `dependency_unavailable` |
| embedding 接口失败（重试后仍失败） | 分析失败，错误码 `upstream_error`；不退回纯字面模式 |
| 字面通道无命中 | 候选集只来自向量通道，正常继续 |
| 候选集为空 | 正常返回空候选，同时输出覆盖缺口；不报错 |
| 素材无向量 | 只参与字面通道，报告体现向量覆盖率 |
| 线索要素为空 | 视为契约违规，拆解环节即失败（`elements` 为必填） |

## 十一、评测口径

与 `docs/产品方案.md` 第十节一致：

- **基线**：纯关键词子串匹配（热点文本切片后直接在素材文案里做包含判断）。
- **对照**：本契约的双通道召回 + RRF 融合 + 要素加权。
- **指标**：Top-5 命中率、首选命中率、线索覆盖度、单次耗时、单次成本。
- **样本**：20 组标注用例，覆盖明星运动、节目影视梗、节日节气、生活方式、职场五类场景。
- 评测脚本属于 P2 阶段任务（见 `docs/backlog.md` 的 S2.8），结果回填到产品方案 §10.2。
