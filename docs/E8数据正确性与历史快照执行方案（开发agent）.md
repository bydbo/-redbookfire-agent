# E8 数据正确性与历史快照执行方案（开发 agent 派发版）

**文档位置：** `docs/E8数据正确性与历史快照执行方案（开发agent）.md`

**文档基线：** 2026-10-20，代码提交 `a676df0`，E6 已完成正式切换及独立验收。
**交付范围：** 本次仅交付方案文档，不实施 E8。本文已落盘，供后续开发 agent 按批次执行；文档交付不代表 S8.0–S8.3 已实现或通过验收。

## 一、目标、边界与完成标准

### 1.1 目标

完成 S8.0–S8.3，使历史运行展示和后续改稿使用明确保存的历史依据：

- 同一热点再次分析、线索变化，不改变旧运行的线索和初稿。
- 素材编辑、重新索引、移入回收站、永久删除，不改变旧运行的候选标题、匹配理由、分数、排名和初稿。
- 当前素材状态与历史依据分别展示。
- 旧数据明确说明来源和缺失，不把切换时采集的数据冒充运行时快照。
- API、结果页、聊天结果卡片、HTML／Markdown 报告使用同一历史数据投影。

**M13 的完成条件是实现、回归、恢复演练、正式切换和独立验收全部通过。** 仅完成迁移文件或单元测试不能关闭 M13。

### 1.2 已确认的产品决定

| 问题 | 本方案采用的决定 |
|---|---|
| 旧运行没有真正快照 | 冻结可得数据，并区分原运行记录、E6 迁移归档、E8 切换时采集和缺失 |
| 删除素材后改稿 | 历史文字依据完整时允许；依据不完整时，在调用模型前明确拒绝 |
| 历史图片 | 不额外复制原媒体或缩略图；不可访问或版本不符时显示原因 |
| 恢复素材 | 沿用 E6：生成新 UUID，不自动恢复旧关联 |
| E6 去重结果 | 不恢复被合并的重复候选，不重排旧排名、不补足 Top-k |
| 历史报告稳定性 | 保证依据与业务数据稳定，不承诺 HTML 字节、页面样式或媒体链接永远不变 |

### 1.3 范围限制

不在本批引入素材版本仓库、媒体永久归档、内容去重、多素材库、通用事件溯源或完整任务恢复框架；不修改检索排序公式，不完成 E7 M18，不展开 E9 效果评测。

默认不新增付费模型调用，不修改业务 prompt 文案。自动验收采用固定模型与向量样本，真实数据库、队列和浏览器必须实际运行。

本方案不构成 E8 正式数据库切换授权；此前 E6 授权不延伸至 E8。

## 二、当前事实与必须修复的链路

接手时先读仓库 `AGENTS.md`，检查实际 Git 状态及 Alembic head，保留已有无关删除和未跟踪文件。

E6 交接时正式库为 `0013`：26 条规范素材、98 条候选、19 条别名、221 条迁移归档。上述数量是交接基线，正式实施时重新盘点，不写成永久断言。7 个原媒体文件缺失，其数据库记录已保留。

当前主要问题：

| 链路 | 当前行为 | E8 要求 |
|---|---|---|
| 分析提交／线索复用 | 预置线索覆盖共享 `hotspots.clue`，worker 继续读取共享值 | 提交时绑定本次输入，执行时只消费运行自己的线索 |
| 历史详情 | 读取共享热点线索，并关联当前 `materials` | 从已冻结的运行依据读取 |
| 候选删除 | `run_matches.material_id` 对素材使用删除级联 | 删除当前素材不能删除历史候选 |
| 报告 | 使用当前配置、当前向量覆盖率，重新计算缺口建议 | 使用本次运行保存的配置、统计和建议 |
| 改稿 | 按基础稿素材 ID 查询当前素材 | 消费基础版本绑定的历史证据 |
| 预览 | 主要通过当前素材 ID 读取关键帧 | 历史预览必须校验归属和版本，不误显示同路径的新内容 |

重点入口为运行读写服务、分析工作流、素材生命周期服务，以及聊天产物版本服务。不要只修改结果页查询而遗漏提交、worker、报告和改稿消费者。

## 三、数据与接口设计

### 3.1 证据来源与完整度

统一定义快照元信息，至少包含：

- `schema_version`
- `origin`
- `captured_at`
- `source_ref`
- `digest`
- `completeness`
- `missing_fields`

`origin` 固定为：

| 值 | 含义 |
|---|---|
| `runtime` | 新流程执行时实际采用并保存的数据 |
| `legacy_run_record` | 旧库中原本就按运行保存的字段，如初稿、分数和理由 |
| `migration_capture` | 来自校验通过的 E6 迁移归档 |
| `cutover_capture` | E8 切换时从当前记录采集 |
| `missing` | 无可用证据 |

`completeness` 使用 `complete / partial / missing`。完整度与来源独立：字段完整的切换采集数据，也不能标为运行时快照。

不同来源的字段组分别记录元信息，不能用一个顶层 `runtime` 标签覆盖混合来源。

### 3.2 持久化结构

优先扩展现有表，不建立第二套运行结果存储。

| 对象 | 新增内容及职责 |
|---|---|
| `runs` | `execution_snapshot`、`evidence_meta`：保存实际执行配置、模型标识、实现／prompt 标识及其来源 |
| `run_hotspots` | 原文快照、线索快照、缺口建议快照、检索元信息及证据元信息 |
| `run_matches` | `material_snapshot`、`evidence_meta`：保存该候选实际使用的素材摘要与版本标识 |
| `chat_artifact_versions` | `evidence_snapshot`：保存该版本改稿使用的线索、素材文字依据和来源 |
| E8 迁移批次表 | 保存规则版本、代码版本、数据库身份、计划摘要、来源摘要、应用计数及核验结果 |

现有 `coverage`、`draft`、`score`、`rank`、`hits`、`missing`、`reasons`、`usage` 继续作为对应结果的权威字段，不再复制一份可独立修改的同义数据。

`run_matches`：

- 保留 `(run_hotspot_id, material_id)` 主键和排名约束。
- 移除 `material_id → materials.id` 外键及删除级联。
- 保留 `run_hotspot_id → run_hotspots.id` 级联。
- `material_id` 成为不可随当前素材生命周期改写的历史身份。
- 不采用 `SET NULL`，不在删除时抹去原身份。
- 当前素材是否存在，通过读侧查询形成动态状态，不写回历史字段。

旧数据确实缺失的字段允许为 `NULL`，同时必须有缺失说明。不能为通过约束生成虚假的标题、空线索或当前模型名称。

### 3.3 快照内容

**运行执行快照**

采用允许名单保存实际解析后的配置，至少覆盖：

- 文本模型 provider／model、影响生成的参数。
- embedding 是否启用、模型和维度。
- 实际生效的检索参数、Top-k、排序权重、阈值、时间基准。
- 实现版本、实际参与任务的 prompt 版本及模板摘要。
- 现有 `context_snapshot` 所绑定的约束来源。

不得保存密钥、完整环境变量、带凭据的地址或整个配置对象。

**热点检索快照**

保存本次检索时的素材数量、向量覆盖率、各通道召回数、候选数及索引清单摘要。索引摘要依据同一数据库读快照中的素材身份、指纹、索引时间、embedding 模型等生成。

这用于标识当时的索引状态，不承诺在未保存向量和全库历史内容的情况下完整重放检索。

**素材快照**

保存实际进入匹配解释和撰稿的素材内容，包括 UUID、规范路径、类型、标题、描述、标签、要素、来源、媒体属性、指纹、索引时间及 embedding 模型。

保留关键帧引用；新捕获的可访问关键帧记录内容摘要。不要复制媒体文件，不将现有 `mtime + size` 指纹称为媒体内容哈希。

### 3.4 公共接口

保留现有运行详情和报告路由，调整响应契约：

- `RunDetail` 增加执行快照摘要与证据说明。
- `HotspotResult` 增加热点执行状态、错误和证据说明；缺失线索允许为 `null`。
- 历史候选的 `material` 表示冻结摘要；确实无法恢复时允许为 `null`。
- 候选增加独立的当前素材状态及预览可用性，不能用当前字段覆盖历史摘要。
- 明确区分“原本没有候选”和“旧候选完整性无法确认”。

历史候选读取不再使用会过滤已删除素材的内连接。

新增运行范围的关键帧读取路由：

`GET /api/runs/{run_id}/hotspots/{position}/candidates/{rank}/keyframes/{index}`

该路由根据运行中的候选定位快照，检查当前身份、允许目录和关键帧摘要；删除、越界、缺失或版本不符返回明确不可用结果。不得接受客户端传入任意文件路径。

现有素材详情及素材关键帧路由继续服务当前素材库。

这是响应语义及可空性调整，必须同步 OpenAPI、后端响应模型、生成的前端类型和全部消费者；不能称为对旧客户端完全透明。

## 四、运行、历史迁移与生命周期规则

### 4.1 新运行写入时机

1. **提交时冻结输入。**
   原文、用户提供的线索和适用约束随运行保存。有可复用缓存线索时，在提交事务中复制到本次运行；没有时明确标为待生成。此后不能因为另一运行更新共享热点而改变输入。

2. **执行开始冻结配置。**
   保存本次实际生效配置。重试不得静默换用变化后的配置或 prompt；无法按既有绑定继续时明确失败，重新分析创建新 run。

3. **生成线索后立即保存。**
   后续检索、解释、撰稿均读取该运行线索。共享 `hotspots.clue` 可以继续作为缓存，但不再是历史读取源。

4. **检索时冻结素材内容。**
   查询向量准备好后，在专用、短生命周期的一致性读事务中完成召回、素材读取及相关统计；事务结束后再调用解释模型，避免长事务包住模型请求。后续写回使用已读取的素材对象，不能重新查询当前素材补快照。

5. **解释完成后保存候选依据。**
   将候选摘要、理由、分数、排名、覆盖度和检索元信息事务化保存，再进入撰稿。解释失败不得把规则解释伪装成已完成的模型解释。

6. **保存建议和初稿。**
   缺口建议按执行结果保存；撰稿失败保留之前已完成的线索和候选，标记热点失败，不用空数组覆盖已保存依据。

7. **终态禁止改写。**
   取消“成功结果先删后插”的覆盖方式。写入使用行锁及阶段／执行代次校验：相同结果重复提交幂等，不同结果不能覆盖已接受快照；旧代次迟到写入拒绝。已经终结的 run 重新分析必须获得新 run_id。

本批只补保证快照正确性所需的写入保护，不扩展成通用任务治理系统。

### 4.2 统一读取与报告

建立统一历史结果投影，供运行详情、聊天读取、结果卡片和报告使用：

- 原文、线索、素材文字、理由、分数、排名、覆盖度、建议、初稿和执行配置来自冻结记录。
- 当前素材存在性、文件可读性、预览状态作为独立附加信息。
- 读取不能触发回填、重算、模型调用或历史字段更新。
- HTML 和 Markdown 都使用同一投影，不再查询当前库统计或当前模型配置补历史元信息。
- 多热点按原 position 输出，成功和失败热点不因渲染路径不同而重排。
- 本地生成报告与 API 报告使用同一业务数据构建逻辑；媒体可用性变化不要求整份报告字节不变。

### 4.3 旧数据回填

回填是显式迁移，不在 GET 请求中自动执行。

采用以下规则：

1. 原有运行级初稿、覆盖度、候选分数／排名／理由等逐字段保留，来源为 `legacy_run_record`。
2. E6 归档通过批次、清单和摘要校验后，才能用于补充素材依据。
3. 对被 E6 合并的候选，依据 `candidate_decisions.original_material_id` 和对应归档定位原候选素材，不能只按路径或标题猜测。
4. 无匹配归档时，从切换时仍存在的对应素材采集，标为 `cutover_capture`。
5. 共享热点线索只能标为切换时采集，不能当作原运行线索。
6. 无法证明原运行模型、检索配置或库统计时保留未知，不拿当前配置填充。
7. 不解析自然语言报告或聊天正文来猜测结构化历史，不调用模型补历史。
8. 不恢复 E6 去重前的重复候选；早已因删除级联消失的候选无法确认完整性时，标记缺口，不承诺完整恢复。
9. 缺失证据可以按缺失状态迁移；归属冲突、摘要校验失败或来源不唯一必须阻断计划，不静默任选。
10. E6 归档和别名保持不变，本批不得清理。

### 4.4 删除、恢复与预览

以下操作都不能删除或修改历史文字依据：

- 编辑素材标题、描述、标签。
- 同路径文件更新及重新索引。
- 移入回收站。
- 永久清理回收站。
- 完整扫描发现文件消失并移除索引。

当前素材删除后，历史候选保留原 UUID；恢复或同路径重新上传产生新 UUID，历史引用不自动绑定新对象。

预览规则：

- 不新增历史图片副本。
- 当前素材已删除时，不通过残留缓存继续提供该素材预览。
- 当前 UUID 仍存在时，只有允许目录内、版本校验通过的关键帧可以展示。
- 旧快照无法证明图片版本时，显示“历史预览无法确认”，不要展示可能已被覆盖的新图片。
- 原媒体缺失与关键帧缺失分别表达，不将二者混为一谈。

### 4.5 基于历史依据改稿

改稿依据顺序固定：

1. 用户选定基础版本自身的 `evidence_snapshot`。
2. 旧基础版本没有证据时，按其 run、热点位置及素材 ID，唯一定位对应运行快照；允许经过已验证的 E6 别名映射。
3. 无法唯一定位或必要文字依据不完整时，在模型调用前返回 `historical_evidence_incomplete`。

禁止退回当前素材、第一候选、最新运行或最新产物 head。

必要依据包括可解析线索、完整基础稿、确定的素材身份，以及撰稿／改稿实际需要的素材文字字段。合法空列表不等于字段缺失。

新版本认领时绑定基础版本和证据摘要；成功版本保存实际使用的证据。沿用现有版本认领、CAS 和幂等语义，不修改旧版本正文。

删除素材后的改稿结果明确提示“基于历史文字依据生成，原素材当前不可用”；不能暗示媒体仍可直接使用。旧数据使用切换采集依据时，同时保留来源提示。

每批仅提交本任务内容，保留检查结果。不得在结构或 API 尚不兼容时让新旧 API／worker 混跑。

## 六、验收矩阵

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| E8-01 | 同一原文先后提交线索 A、B | 两次运行分别使用 A、B；旧运行及初稿不变 |
| E8-02 | A 排队期间 B 修改共享热点 | A 不读取 B 的线索 |
| E8-03 | 检索后、解释／撰稿期间编辑或删除素材 | 结果保留实际采用的素材摘要，写回不因素材外键失败 |
| E8-04 | 修改标题、标签、描述并重新索引 | 旧标题、理由、排名、分数、初稿逐字段不变 |
| E8-05 | 回收站、永久删除、扫描删除 | 历史候选数量及文字依据不变，当前状态准确 |
| E8-06 | 同路径恢复／重新上传 | 新 UUID；旧候选、别名和改稿依据不绑定新素材 |
| E8-07 | 修改当前模型、阈值、库数量或向量覆盖率 | 旧运行元信息和报告依据不变 |
| E8-08 | 缺口建议规则变化 | 旧建议不重新计算 |
| E8-09 | 删除后基于完整快照改稿 | 使用原快照，生成新版本，原稿与旧版本不变 |
| E8-10 | 快照缺失、身份歧义、错误基础版本 | 调用模型前拒绝，模型调用计数为零 |
| E8-11 | 重复投递、节点重试、旧代次迟到写入 | 不覆盖已接受结果，不产生重复候选 |
| E8-12 | 某热点失败／无候选／撰稿失败 | 区分失败、合法空结果和旧数据缺失；保留已完成依据 |
| E8-13 | E6 归档补充及旧数据回填 | 来源标签准确，不恢复重复候选、不伪造 runtime |
| E8-14 | 计划或归档被修改、版本漂移、数据库身份不符 | apply 阻断；无部分回填 |
| E8-15 | 同一计划重复执行 | 不重复批次、不覆盖既有完整快照 |
| E8-16 | 图片缺失、覆盖、越界、链接及同路径新媒体 | 不泄漏目录、不显示错误历史图片 |
| E8-17 | 详情、聊天卡片、HTML、Markdown | 历史业务字段一致，缺失说明一致 |
| E8-18 | 宿主与容器交替索引 | 延续 E6 的 UUID 稳定和无重复保证 |
| E8-19 | 备份恢复与旧版本读取 | 隔离恢复后受保护数据一致；回退边界有实证 |

必需质量门：

- 后端 lint、mypy、相关回归及完整单测／真实容器集成测试。
- 使用现有联合覆盖率入口，门槛 **≥78%**，保留单测、集成和联合报告。
- OpenAPI 一致性与前端生成类型防漂移。
- 前端 lint、测试、类型检查、构建。
- Compose 校验及最终镜像构建。
- 真实临时 Postgres／Redis／API／worker／浏览器闭环；不以伪造 HTTP 响应代替。
- 查看浏览器截图和实际 HTML／Markdown 报告。
- 记录迁移耗时、读取耗时、快照体积和查询数量；避免逐候选查询，不编造未约定的性能阈值。

Docker、权限或依赖阻止必需检查时，状态保持待验收；不能跳过后关闭 M13。

## 七、迁移、正式切换与交接

### 7.1 迁移工具

提供显式 `plan / apply / verify` 管理入口，默认只读计划。

计划绑定：

- 数据库名称、OID、集群身份与 schema。
- 固定代码版本、规则版本。
- 来源表摘要、目标字段和逐类计数。
- 每条回填的来源、完整度与缺失原因。
- 计划摘要和确定性批次 ID。

统一 UTC 及无损数值编码。apply 在事务内重新核对来源和计划；任何冲突整体回滚。不得直接复用 E6 批次类型，把 E8 快照回填伪装成身份合并。

结构分两阶段：先扩展字段与迁移记录，再完成回填和核验，最后移除素材级联并收紧快照约束。正式切换期间保持停写。

### 7.2 正式切换步骤

开发 agent 先完成：

1. 固定候选提交与镜像。
2. 正式数据只读盘点及隔离副本演练。
3. 最终预期影响、缺失分布、回填来源统计。
4. 备份恢复与旧版本读取证明。
5. 独立验收及具体切换包。

随后申请一次明确授权，覆盖停写、备份、结构迁移、回填、约束收口、版本部署和恢复服务。

批准后执行：

1. 暂停 API、排空 worker，核实无在途任务和其他写连接。
2. 制作最终备份，记录校验和，并恢复到隔离库验证。
3. 生成最终计划；与批准范围不符即停止。
4. 执行扩展、回填、精确核验和约束收口。
5. API／worker／管理工具统一切至候选版本。
6. 只读检查旧运行、报告、别名、缺失标记和可用预览。
7. 恢复服务，保存正式执行记录。

正式素材不得用于删除／恢复冒烟。新增行为验证在临时素材和隔离全栈完成。

失败后不得直接启动不兼容旧版本。正式恢复旧备份需要另行授权并保全切换后的新增数据；schema downgrade 不等于数据恢复。恢复业务后的日常审计不能继续要求数据与停写计划完全相等。

### 7.3 最终交付清单

开发 agent 必须交付：

- 契约及 ADR。
- 实现、迁移工具和测试提交。
- 旧数据来源／缺失统计。
- 完整验证结果与浏览器、报告证据。
- 固定镜像、迁移计划、批次和备份校验信息。
- 正式切换及独立验收结论。
- E8 验收报告与更新后的 backlog。

真实数据、媒体、备份、凭据和原始运行证据留在受忽略的本地目录；可提交报告使用脱敏摘要。

**最终状态规则：S8.0–S8.3 全部满足验收且正式切换成功，才能关闭 M13。E7 M18 保持原状态；E8 结束不等于真实模型效果已被验证。**
