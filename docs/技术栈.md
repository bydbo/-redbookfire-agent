## 一、当前技术栈（已落地）

| 层面 | 选型 | 依据 |
| --- | --- | --- |
| 语言 | Python，要求 `>= 3.11` | `pyproject.toml` 的 `requires-python`；代码使用了 `tomllib`（3.11 才进入标准库） |
| 解释器 | 3.12.14（uv 管理的虚拟环境） | `.venv\Scripts\python.exe -V` |
| 包管理与构建 | uv 0.12.7 + `pyproject.toml`（PEP 621）+ hatchling 后端 + src 布局 | `pyproject.toml`、`uv.lock` |
| 运行时依赖 | **无**，仅 Python 标准库 | `dependencies = []`；全量 import 见第二节 |
| 开发依赖 | pytest 9.1.1 | `uv.lock` 共锁定 7 个包，除本项目外全部是 pytest 及其传递依赖 |
| 文本模型接入 | OpenAI 兼容 `/chat/completions` 协议，标准库 `urllib` 直连，**未使用官方 SDK** | `src/xhs_agent/tools/llm.py` |
| 文本模型默认值 | DeepSeek（`deepseek-chat`，`https://api.deepseek.com/v1`） | `config/config.toml` |
| 结构化输出 | 请求携带 `response_format: {"type": "json_object"}`；解析失败时把错误回灌给模型自修重试 | `tools/llm.py` 的 `StructuredCaller` |
| 多模态接入 | 通义千问 VL（`qwen-vl-max`），走 DashScope 的 OpenAI 兼容端点，关键帧转 base64 内联 | `src/xhs_agent/tools/vision.py` |
| 音视频处理 | ffmpeg / ffprobe，通过 `subprocess` 调用（**可选**，缺失时跳过抽帧） | `src/xhs_agent/tools/media.py` |
| 检索算法 | 字符二元组（bigram）Jaccard + 包含度启发式 + 要素类型加权；**无 embedding、无向量库** | `util.py` 的 `text_similarity`、`matching.py` |
| 配置 | TOML（标准库 `tomllib`）+ 自研极简 `.env` 解析 + 环境变量覆盖，三层优先级 | `src/xhs_agent/config.py` |
| 数据落地 | JSON（素材索引）、JSONL（运行轨迹）、Markdown 与单文件 HTML（报告，CSS 内联）；**无数据库** | `tools/materials.py`、`tools/trace.py`、`tools/report.py` |
| 测试 | pytest（`tests/` 目前为空目录，0 用例） | `pyproject.toml` 的 `testpaths` |
| 版本控制 | Git 本地仓库，`main` 分支，Conventional Commits | — |

**尚未引入**：Web 框架、数据校验框架、数据库、向量库、容器化、CI、静态检查与格式化工具、结构化日志。

## 二、运行时依赖清单（标准库）

源码全部 import 如下，均为标准库，无第三方：

```
__future__  base64  contextlib  dataclasses  datetime  hashlib  html
json  os  re  shutil  struct  subprocess  time  tomllib
typing  unicodedata  urllib
```

**唯一的外部程序依赖**是 `ffmpeg` / `ffprobe`：通过 `shutil.which` 探测，缺失时不报错、直接降级。

## 三、规划中的企业化演进

以下组件**尚未引入**。列在这里是为了统一方向；引入时必须走 `AGENTS.md` 第 6 节流程，落地后把条目从本节移到第一节。

### 阶段一 · 工程骨架

| 组件 | 解决什么 |
| --- | --- |
| Pydantic v2 | 替换 `schemas.py` 的 dataclass，把数据契约升级为带校验的模型 |
| FastAPI + Uvicorn | 提供 `POST /analyze`、`GET /runs/{id}`、`GET /health` 接口层 |
| httpx | 替换 `urllib`，获得连接池、超时重试与异步并发能力 |
| ruff + mypy | 静态检查与格式化，纳入 CI |
| pytest-cov + pytest-asyncio | 覆盖率统计与异步用例 |
| pre-commit | 提交前自动拦截 |
| GitHub Actions | lint + typecheck + test 三关流水线 |
| Docker + docker-compose | 一条命令起服务 |

### 阶段二 · 检索与数据架构

| 组件 | 解决什么 |
| --- | --- |
| Embedding 模型 | 补上字面匹配抓不到的近义表达（例如"挥拍"与"杀球"） |
| 向量库（pgvector 或 Chroma） | 语义召回 |
| 混合检索 + RRF 融合 | 关键词召回与向量召回融合排序，用评测集量化提升幅度 |
| PostgreSQL + pgvector | 素材索引与运行记录从 JSON 文件迁到数据库 |
| asyncio + 信号量 | 控制模型调用并发，避免超限 |

### 阶段三 · 按岗位决定

LangGraph 或 pydantic-ai（把三层分工表达为显式编排）、function calling 规范化、可观测（Langfuse / OpenTelemetry）、评测框架（ragas / promptfoo）。

**取舍提醒**：引入 LangGraph 与现有的"确定性检索 + 模型只在两端"是两种不同叙事，容易互相矛盾。要么用框架把编排显式化并讲清理由，要么保留自研编排并把取舍讲透，不要两个都上又都讲不清。

## 四、明确不引入

Kubernetes、Kafka、微服务拆分、gRPC。

理由：本项目没有对应的业务量支撑（单机、单用户、无并发压力），引入后无法回答"为什么需要它"，属于负收益。

## 五、口径与红线

1. **简历与文档只能写已经落地的技术栈。** 规划中的组件留在第三节，落地之前不得出现在任何"已使用"表述里。
2. **每个依赖都要能回答"不加它会怎样"。** 纯粹为凑关键词而引入的组件，会在面试里留下追问口子。
3. 引入或移除任何依赖后，同一次改动必须同步：`pyproject.toml`、`uv.lock`、`README.md`、`AGENTS.md` 第 4 节、本文件。
