### 运行时降级已取消

这是本次定稿最重要的变化：

- **取消**：原设计里"没有密钥就自动降级到离线规则引擎、保证任何机器都能跑通"的整条路径**作废**。
- **现行规则**：缺 API 密钥、连不上数据库、连不上 Redis 时，**启动直接失败并给出明确报错**，不做静默降级。
- **连带影响**：`tools/offline.py`（离线规则引擎）将在第二阶段删除，测试改用固定样本；README、产品方案与简历里的"零密钥可跑"叙事同步移除。
- **边界说明**：取消的是**整条运行链路的降级**。单个可选能力（如无 ffmpeg 时跳过抽帧）属于能力裁剪，缺失时在使用方明确标注，不算降级。
- **理由**：降级模式产出质量差一个档次，一旦被当成正常模式使用会损害结果可信度；同时要求业务代码长期维护两套实现路径，测试与维护成本翻倍。宁可启动就失败，也不要跑出一份不可信的结果。

接口、数据模型、检索算法与配置的**权威定义已移到 `docs/contracts/`**，本文件不再重复维护，避免两处不一致：

| 契约 | 文件 | 内容 |
| --- | --- | --- |
| API 契约 | `docs/contracts/openapi.yaml` | OpenAPI 3.1；六个接口、统一错误码、请求与响应结构 |
| 数据契约 | `docs/contracts/数据契约.md` | 5 张表、字段、索引、枚举与 Alembic 迁移策略 |
| 检索契约 | `docs/contracts/检索契约.md` | 双通道召回、RRF 融合、要素加权、参数表与破坏性变更清单 |
| 配置契约 | `docs/contracts/配置契约.md` | 环境变量全集、config.toml 段结构、启动前置检查与退出码 |

规则：**契约是唯一事实源，代码向契约对齐**；改接口或数据结构必须先改契约文件再改实现（见 `AGENTS.md` 第 2 节与第 10 节）。

`llm.provider` 取消 `auto` 的降级语义：默认即为在线模式，缺密钥启动即失败。
## 四、分阶段落地路线

每个阶段独立可验收，且要求上一阶段测试保持全绿。

| 阶段 | 目标 | 关键内容 | 验收 |
| --- | --- | --- | --- |
| P1 工程骨架 | 契约与质量基线 | Pydantic v2 契约重构、pydantic-settings 配置、ruff + mypy + pre-commit、`tools/` 首批单测 | `uv run pytest` 与 `mypy` 全绿，`tools/` 行为不变 |
| P2 数据与检索 | 持久化与语义召回 | Compose 起 Postgres + Redis、SQLAlchemy async + Alembic、素材索引与向量入库、混合召回 + RRF、删除离线规则引擎 | 20 组评测集跑出"纯字面基线 vs 混合召回"对比数字 |
| P3 编排与服务 | 服务化与异步 | LangGraph 状态图、FastAPI 六个接口、Celery 异步任务、httpx 替换 urllib | 异步接口端到端跑通，OpenAPI 文档页可访问 |
| P4 可观测与交付 | 可运维、可交付 | structlog + run_id、Langfuse、OpenTelemetry、多阶段 Docker 镜像、GitHub Actions CI | `docker compose up` 一条命令起全栈，CI 三关全绿 |

**前置条件**：需启动 Docker Desktop；C 盘仅剩约 33 GB，建议把 Docker 镜像存储位置迁到 D 盘。

## 五、明确不引入

Kubernetes、Kafka、微服务拆分、gRPC、Vault、React/Vite、自建 Langfuse（其 v3 依赖 ClickHouse 与 MinIO，本机不划算）。

理由：本项目没有对应的业务量支撑（单机、单用户、无并发压力），引入后无法回答"为什么需要它"，属于负收益。

## 六、口径与红线

1. **简历与文档只能把"已落地"的组件写成"已使用"。** 第二节的组件在对应阶段验收通过之前，不得出现在简历或任何"已使用"表述里。
2. **每个依赖都要能回答"不加它会怎样"。** 纯粹为凑关键词而引入的组件，会在面试里留下追问口子。
3. **不做运行时降级。** 缺密钥、缺数据库、缺队列时报错是预期行为；任何"静默降级"的实现都属于违规。
4. 引入或移除任何依赖后，同一次改动必须同步：`pyproject.toml`、`uv.lock`、`README.md`、`AGENTS.md` 第 4 节、本文件。
