### 运行时降级已取消

这是本次定稿最重要的变化：

- **取消**：原设计里"没有密钥就自动降级到离线规则引擎、保证任何机器都能跑通"的整条路径**作废**。
- **现行规则**：缺 API 密钥、连不上数据库、连不上 Redis 时，**启动直接失败并给出明确报错**，不做静默降级。
- **已执行（S2.7）**：`tools/offline.py`（离线规则引擎）与 `OfflineProvider` 已删除，测试改用固定样本与假 provider；README、产品方案与简历里的"零密钥可跑"叙事同步移除。
- **边界说明**：取消的是**整条运行链路的降级**。单个可选能力（如无 ffmpeg 时跳过抽帧）属于能力裁剪，缺失时在使用方明确标注，不算降级。
- **理由**：降级模式产出质量差一个档次，一旦被当成正常模式使用会损害结果可信度；同时要求业务代码长期维护两套实现路径，测试与维护成本翻倍。宁可启动就失败，也不要跑出一份不可信的结果。

## 五、明确不引入

Kubernetes、Kafka、微服务拆分、gRPC、Vault、React、Next.js、自建 Langfuse（其 v3 依赖 ClickHouse 与 MinIO，本机不划算）。

理由：本项目没有对应的业务量支撑（单机、单用户、无并发压力），引入后无法回答"为什么需要它"，属于负收益。**前端框架是唯一例外**——它的价值在交互与演示，选择理由见 ADR 0008。

## 六、口径与红线

1. **简历与文档只能把"已落地"的组件写成"已使用"。** 第二节的组件在对应阶段验收通过之前，不得出现在简历或任何"已使用"表述里。
2. **每个依赖都要能回答"不加它会怎样"。** 纯粹为凑关键词而引入的组件，会在面试里留下追问口子。
3. **不做运行时降级。** 缺密钥、缺数据库、缺队列时报错是预期行为；任何"静默降级"的实现都属于违规。
4. 引入或移除任何依赖后，同一次改动必须同步：`pyproject.toml`、`uv.lock`、`README.md`、`AGENTS.md` 第 4 节、本文件。
