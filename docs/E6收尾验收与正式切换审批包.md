## 4. 待批准的执行范围

只有所有隔离验收通过、候选版本固定及独立最终确认后，才申请以下一次切换授权：

1. 暂停 API 入口并排空 worker，检查队列、在途任务及其他写连接；切换期间上传、编辑、回收站、分析和索引不可用。
2. 停写后制作最终 `pg_dump -Fc`，保存 SHA-256、工具／代码／schema 版本，并恢复到另一隔离库验证。正式媒体保持只读。
3. 正式库 `0007→0012` 只扩展结构；以固定提交生成最终计划，核对与上述批准影响一致，再 apply、精确 verify，最后 `0012→0013` 收口约束。不用 Compose 自动迁移抢先直达 head。
4. API、worker、迁移工具统一使用候选版本；复查启动、数据库身份、别名归档、旧运行、报告及可用关键帧读取，不调用付费模型。
5. 全部成功后恢复服务，记录时间、最终批次、计划摘要、备份校验和与结果；更新 M12 和 S6.13，放行 S8.0。

若最终数据变化超出已批准范围，重新审查；apply 失败保持停写并确认回滚。apply 成功后检查失败，优先向前修复，不能直接启动不兼容旧版本。恢复旧正式备份不包含在常规切换授权内，需要保全当前数据并另行确认。
