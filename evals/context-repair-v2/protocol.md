# context-repair-v2 冻结协议

冻结日期：2026-10-18。承接 v1，保留旧协议和既有检索 manifest，不原地改写。

cases.json 包含 12 条具体输入、6 类场景及可观察预期。T01/T02 各 24 轮，其余各 6 轮；
每臂每用例 3 次，两臂共 72 个会话、648 轮。完整两臂为 cbd13f9 + off 与候选提交 + enforce，
必须记录各自实际代码；同代码 off 对照只能标“策略对照”，不能冒充旧代码基线。

本次用户授权模型调用累计 **10 元**；200 元仅为历史规划。运行前持久预留每次请求的保守
上界，正常返回按已知 usage 结算，缺用量或异常保留预留，崩溃后重启不释放未知占用。
预算不足停止并记录未运行输入，不减少计划分母冒充全量通过。视觉图片从冻结 SVG 栅格化，
变换参数及 PNG SHA256 记入结果，不向模型传 SVG。不得用真实私人素材替代冻结输入。

执行入口：scripts/eval_context_repair.py。离线模式核对冻结资产并运行真实回归；模型抽取、
改稿、视觉与前缀分别导出原始记录。该脚本的组件模式不等同于 648 轮端到端全量签收。
浏览器入口：scripts/smoke_context_ui.cjs（依赖本机 Playwright，可通过环境指定模块和浏览器）；
性能入口：scripts/benchmark_context.py（临时 PostgreSQL，200 次状态和 100 次缓存读取）。

scoring.json 是评分事实源。确定性指标和语义评分分开；语义约束与任务成功由独立人工
匿名核对，开发 agent、模型评委及未填写的评分表不能代签。失败、超时、空输出保留在分母。
未运行、环境失败、质量失败、人工待评必须分别报告，不因脚本退出码 0 就标 M18 完成。

固定事件复算由 tests/unit/test_context_metrics.py 验证，请求级消费率与条目队列复用率分开；
新增生产者路径由 tests/integration/test_context_followup.py 核对。正常完整率至少 99%，支持
供应商成功响应完整分项覆盖至少 95%，并单独报告所有尝试覆盖及 unknown。

改变输入、答案、评分和素材必须创建 v3；manifest.json 校验本目录所有冻结文件 SHA256。
